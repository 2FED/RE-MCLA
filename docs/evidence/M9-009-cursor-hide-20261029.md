# M9-009 hide the mouse cursor on pad/wheel input (2026-10-29)

**Status:** implemented as a host-only change, unit tested and compiled.
Not physically verified: nobody has run the built `mcla.exe` with a pad,
wheel or mouse. This is not a physical PASS.

Owner request (2026-10-28, `docs/M9-priorities.md` order 9): while the game
window is focused, gamepad or wheel input hides the mouse cursor and mouse
movement shows it again. No effect when unfocused or in the launcher.

## Design

The SDK already exposes everything a host-only change needs, so the SDK is
not modified:

- cursor state: `rex::ui::Window::SetCursorVisibility` /
  `GetCursorVisibility` / `IsMouseCaptureRequested` (the SDL window applies
  them with `SDL_HideCursor` / `SDL_ShowCursor`);
- focus: the `ReXApp::OnWindowFocusChanged(bool)` hook (UI thread);
- pad, wheel and mouse events: SDL3 `SDL_AddEventWatch`. SDL3 is already a
  public link dependency of the `rexglue` target (`SDL3::SDL3-static`), and
  the SDK's own SDL input driver uses the same mechanism. An event watch is
  required because that driver flushes joystick/gamepad events from the SDL
  queue, so they never reach the window's normal event loop.

Parts:

| File | Role |
|---|---|
| `src/mcla_cursor_autohide.h` | Pure, header-only logic. `PadActivityFilter` decides whether a pad/wheel event is deliberate input. `AutoHideController` maps focus, pad activity and mouse activity to hide/show actions. No SDL, window or thread dependency. |
| `src/mcla_cursor_autohide_sdl.{h,cpp}` | Host adapter: SDL event watch, cross-thread hand-off to the UI thread, and the window cursor calls. |
| `src/mcla_app.{h,cpp}` | New CVar `mcla_cursor_autohide` (default `true`, init-only). The adapter is installed in `OnPostSetup`, fed from `OnWindowFocusChanged`, and removed in `OnShutdown`. |
| `tests/mcla_cursor_autohide_test.cpp`, `CMakeLists.txt` | New nonshipping unit test `mcla_cursor_autohide_test` (under `MCLA_BUILD_DIAGNOSTIC_TESTS`, like `mcla_diagnostic_hotkey_test`); the adapter TU is added to `MCLA_SOURCES`. |

Rules:

- **Pad activity** = a gamepad or joystick button press, a non-centred hat,
  or an axis move of at least 4096 (about 6% of the 16-bit range) away from
  that axis's baseline. The first value of each axis only seeds the baseline;
  after an accepted move the baseline follows the new value. This ignores idle
  noise and resting drift at any rest position (centred sticks, triggers and
  wheel pedals that rest at one end) without per-device knowledge. Button
  releases are not activity. Baselines are kept per (source, device, axis) in a
  fixed 64-entry table (no allocation in the event path) and dropped when the
  device is removed.
- **Mouse activity** = mouse motion with a non-zero delta, a mouse button press
  or the mouse wheel. Zero-delta motion is ignored so a cursor state change
  cannot re-show the cursor.
- **Hide** only when the window is focused, the cursor is currently visible,
  and no mouse capture is requested (the SDK keyboard/mouse driver, `mnk_mode`,
  default off, hides and captures the cursor itself; this feature never fights
  it).
- **Show** on mouse activity, on focus loss, and at shutdown, but only to undo
  a hide this feature made, and only while no capture is active. Motion during
  a capture (including the driver's re-centring) does not reveal the cursor; the
  first mouse activity after the capture ends does. The focus-loss restore is
  deferred until the other focus listeners have run, so the keyboard/mouse
  driver can release its capture first.
- Threading: the SDL watch can run on the UI thread or an SDL joystick thread.
  It only classifies the event (axis baselines under a mutex), and when the
  state would change it queues one coalesced `CallInUIThreadDeferred` pass
  (latest activity wins). All window calls happen on the UI thread. The
  deferred pass holds a `weak_ptr`, so it is a no-op after shutdown. SDL holds
  its watch-list lock while dispatching, so no watch callback is in flight once
  `SDL_RemoveEventWatch` returns.
- The launcher is a separate process and is untouched. With
  `--mcla_cursor_autohide=false` the adapter is never installed.

## Not verified (owner, physical)

- With a pad: in the focused game window, press a button or move a stick; the
  cursor disappears. Move the mouse; it comes back. Leave the pad idle on the
  desk with the cursor visible: it must stay visible (no idle-noise hide).
- With the Logitech wheel: turning the wheel well past a small angle, pressing
  a pedal, or pressing a wheel button hides the cursor; resting pedals do not.
- Alt+Tab away while hidden: the cursor is visible over other windows and
  over the unfocused game window; pad input while unfocused does not hide it.
- Settings overlay or other ImGui panels: mouse movement shows the cursor.
- Steam Deck (Proton): the built-in controls hide the cursor; the trackpad or
  touchscreen as mouse shows it.
- With `input_backend=xinput` the SDL gamepad subsystem is not used, so the
  feature stays inactive (cursor never hidden). Not tested.
