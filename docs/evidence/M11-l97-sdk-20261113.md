## 2. Low latency replaces strict

### Cvars (GPU/D3D12, rexgpu-xenos, hot reload)

| cvar | default | meaning |
|---|---|---|
| `d3d12_frame_lead_strict_low_latency` (int 0..2) | 0 | 0: strict decided by `d3d12_frame_lead_strict` only (as l96). 1: at every frame open at which the low-latency sleep is active the frame's strict mode is 0 (off). 2: it is 2 (adaptive). Otherwise the configured `d3d12_frame_lead_strict` on that same frame |
| `d3d12_frame_lead_strict_low_latency_antilag2` (bool) | false | an active Anti-Lag 2 sleep also counts (untested; Reflex only by default) |
| `d3d12_frame_lead_strict_low_latency_guard_frames` (int 0..16384) | 2700 | guard window: the last N frames opened with the bound replaced; 0 = no guard |
| `d3d12_frame_lead_strict_low_latency_guard_lead2` (int 0..16384) | 80 | more than this many lead-2 frames in the window latch the configured mode for the session |

The literal rule is kept for mode 2 with `d3d12_frame_lead_strict=0`: while active the frame
runs adaptive (stricter than the configured off). No arm uses that combination.

### "Active" (evaluated at every frame open, `EvaluateLeadActive`, pure)

All must hold, otherwise the first failing reason (the name goes into the state line):
1. `undecided`: the layer has made its lazy activation decision (first frame call after the
   device);
2. `init`: a backend is active (mode not off, init ok, not shut down);
3. `wine`: not under Wine (even with `d3d12_low_latency_allow_wine`);
4. `backend` / `antilag2`: the backend is Reflex, or Anti-Lag 2 with the `_antilag2` cvar;
5. `markers_only`: not `d3d12_low_latency_markers_only` (as of the last simulation start);
6. `no_sleep`: a driver sleep call has happened;
7. `sleep_off`: the sleep is not turned off for the session (the l95 back-off after three
   sleeps over 250 ms);
8. `sleep_failed`: the last sleep call succeeded;
9. `stale_sleep`: the last sleep was for the current or the previous guest swap
   (`LeadSleepFresh(last_sleep_frame, guest_swaps)`: `last_sleep_frame >= guest_swaps`, where the
   sleep of frame N is made at its simulation start with id = swaps so far + 1). A frame without
   a simulation start (loading) makes the sleep stale at the next VdSwap, so strict applies.

### Exposure to the command processor

No new thread, no lock. The l95 controller publishes, into the runtime's global `LeadAtomics`
(survives shutdown): `guest_swaps` (at every VdSwap), `markers_only` and `sleeping` (at every
simulation start and after every sleep), `last_sleep_ok` and then `last_sleep_frame` (release
store after each driver sleep). `QueryLeadState()` reads them plus the activation state (`g_state`)
and the backend kind / Wine flag stored at activation, all with atomic loads. It is called only
when `d3d12_frame_lead_strict_low_latency != 0` (one cvar read per frame open otherwise).

### Per frame (`FrameLeadLowLatencyState`, pure)

- Frame open (`BeginSubmission`, before the l91 strict block): `OnFrameOpen(configured, mode,
  active)` returns the effective mode (`FrameLeadEffectiveStrictMode`: the configured mode when
  the mode is 0, not active, or the guard latched; else 0 or 2), which replaces the l91
  `strict_mode` for that frame (the adaptive hold resets whenever the frame's mode is not
  adaptive, as before). Counted: replaced (`lead_ll_active_frames`), requested but not replaced
  (`lead_ll_fallback_frames`), every open by effective mode (`lead_ll_eff_hist`), active/inactive
  transitions (`lead_ll_changes`).
- Frame end (`EndSubmission`, after the l78 frame-end gauge): only frames opened with the bound
  replaced enter the guard window (frame-end gauge >= 2 = lead-2). More than G lead-2 frames among
  the last W such frames latch the configured mode for the session (mode toggles do not clear
  it), one line.

### Guard defaults: W = 2700, G = 80 (trip at 81 = 3.0 %)

From the l96 reflex-nostrict session (14 minute lines, frames / lead-2 frames): 1934/53 (the
loading minute, 2.7 %), 2877/0, 2617/2, 2812/30, 2674/0, 2647/8, 2931/26, 2618/0, 2771/29,
2726/2, 2741/7, 2783/40 (largest driving minute, 1.4 %), 2614/1, 2927/12: 210 in 37672 frames
(0.56 %). A 2700-frame window spans at most two adjacent minute lines (every minute here has
>= 1934 frames), and no two adjacent minutes sum to more than 53, so no window of that run
exceeded 53 lead-2 frames: below 81 with a margin of 28. The l90 limit-1 run that flickered had
91-94 lead-2 frames per minute, above 80. The window of 600 frames suggested in the brief was
not used: the l96 data give only per-minute counts, so the peak of a 13-second window is not
known, while for a one-minute window it is bounded by the data. Unit test: the 14 minutes with
every minute's lead-2 frames packed at the minute edges (two layouts that merge adjacent
minutes) never trip and never exceed 53 in the window; 1 lead-2 frame in 30 trips at frame 2430.

### Lines

- `MCLA_LEAD_LL v=1 kind=state active=<0|1> reason=<r> frame=<cp frame> ll_mode= configured_strict=
  effective_strict= latched=`: at the first open with the mode on and at every active/inactive
  change (at most 256 per session, then one `kind=state_lines_capped max=256 frame=` line; the
  changes are still counted).
- `MCLA_LEAD_LL v=1 kind=guard_trip frame= lead2_in_window= window_filled= guard_frames=
  guard_lead2= strict_now= (latched for the session)`: once.
- `MCLA_READBACK v=1` minute and mark lines, appended at the very end (after the l92
  `rb_age_inject*` fields; always present): `lead_ll_mode= lead_ll_active_frames=
  lead_ll_fallback_frames= lead_ll_guard_trips= lead_ll_eff_hist=<off>,<strict>,<adaptive>
  lead_ll_latched= lead_ll_changes= lead_ll_window_lead2_max= lead_ll_guard_frames=
  lead_ll_guard_lead2=` (counts per minute; latched and the guard cvars are the current state).
  `lead_strict=` keeps printing the configured `d3d12_frame_lead_strict`.

## 3. `d3d12_low_latency_mode=auto`

`SelectBackend` (pure) now: auto = Reflex on NVIDIA; Anti-Lag 2 on AMD only when the new cvar
`d3d12_low_latency_auto_antilag2` (UI/D3D12, bool, default false, read once) is true (reason
`auto_antilag2` otherwise); none elsewhere (`vendor`); none under Wine even with
`d3d12_low_latency_allow_wine` (`wine`). The explicit `reflex` and `antilag2` modes are unchanged
(they still honour `allow_wine`). l95 behaviour of auto on AMD (Anti-Lag 2) is therefore changed;
the existing l95 test was updated accordingly.

## 5. Not done / limits / risks

- Nothing has run in the game: whether the Reflex sleep counts as active during normal play
  (expected: all driving frames), how often it flips around loading screens, and whether the
  guard ever trips in a long soak are all unobserved.
- The stale-sleep rule is strict: one frame without a simulation start (the l96 logs show a few
  sim-per-swap mismatches around loads) falls back to strict for one or two frames. Intended.
- The lead-2 guard is reactive: up to 80 lead-2 frames (and their late fences) in a window are
  allowed before strict returns. The flicker risk of those frames is what the soak and the dawn
  run measure.
- The CP reads the guest-side atomics without synchronising with the guest frame; a sleep that
  lands between the read and the open is seen at the next open (one frame late). Benign.
- Version string: the CMake version is `0.20.0.8-dev.g6c5792d`; the published fork release
  v0.20.0.8 is a different commit (`c63895c`); the `-dev.g` suffix distinguishes them.
