## What changed and why

1. **Vendored SDL** (`src/joystick/windows/SDL_windowsjoystick.c`,
   `SDL_xinputjoystick.c`, `SDL_xinputjoystick_c.h`). This targets root
   causes 1 and 2 of the analysis: SDL re-scans XInput only after a HID
   device-interface notification.
   - `WINDOWS_JoystickDetect` first calls `WINDOWS_PollXInputHotplug()`. At
     most once per `SDL_XINPUT_HOTPLUG_POLL_MS` (1000 ms), this reads
     `XInputGetCapabilities` for users 0-3. If the connected mask differs
     from the mask the last `SDL_XINPUT_JoystickDetect` observed, it calls
     `SetWindowsDeviceChanged()`. That triggers the normal DirectInput+XInput
     re-enumeration, which emits the removal of a stale device and an add
     with a new instance ID.
   - **Changes from the proposal diff, following the analysis' risk section:**
     - *Compared mask.* The poll compares against the mask that enumeration
       actually saw. `SDL_XINPUT_GetDetectedUserMask`, a new accessor, is
       set inside `SDL_XINPUT_JoystickDetect` for every user that reports
       `ERROR_SUCCESS`, including devices that `AddXInputDevice` skips. The
       proposal compared against its own previous poll. That version could
       miss a pad that came back between the poll sample and the rescan's
       own XInput query.
     - *When the poll runs.* It is armed only after the first enumeration.
       It never runs while `SDL_XINPUT_Enabled()` is false (hint
       `SDL_XINPUT_ENABLED=0` or the XInput DLL failed to load) or while
       `XINPUTGETCAPABILITIES` is null. It is also skipped while RawInput is
       enabled: RawInput has its own hotplug, and the upstream comment in
       `AddXInputDevice` warns that XInput calls can upset wireless adapters
       that RawInput holds.
     - *Shutdown.* `WINDOWS_JoystickQuit` resets the poll state, and
       `SDL_XINPUT_JoystickQuit` resets the detected mask, so the subsystem
       can be re-initialised cleanly.
   - **Unchanged:** DirectInput enumeration, device matching and path reuse.
     The patch only decides when the existing rescan runs. All state is
     touched only under the joystick lock (Detect/Quit).
2. **SDK driver** (`src/input/sdl/sdl_input_driver.cpp`).
   - New cvar `hid_sdl_rawinput`, default `false`, labelled experimental.
     When set, it calls `SDL_SetHint(SDL_HINT_JOYSTICK_RAWINPUT, "1")` before
     `SDL_InitSubSystem(SDL_INIT_GAMEPAD)` and logs that it did so. The
     `hid_` prefix follows the existing `hid_mappings_file` pattern.
   - The `SDL OnControllerDeviceAdded` log line now ends with
     `Instance(<SDL instance id>), Backend(<xinput|hidapi|rawinput|wgi|gameinput|virtual|dinput-or-other>), Path("<XInput#N|withheld|none>")`.
     The backend comes from the driver signature in GUID byte 14.
     - **Deviation from the proposal:** the proposal logged
       `SDL_GetGamepadPath` verbatim. Non-XInput backends return OS
       device-interface paths, which can contain serial numbers or Bluetooth
       addresses. Only `XInput#N` is logged verbatim; any other path is
       logged as `withheld`.
   - Helpers `SdlJoystickBackendName` and `PrivacySafeSdlDevicePath` were
     added to `include/rex/input/sdl/slot_mapping.h` so they can be unit
     tested.
3. **Tests** (`tests/unit/input/sdl_slot_mapping_test.cpp`): three new
   cases, tagged `[hotplug]`.
   - Remove and re-add with a new instance ID re-binds guest slot 0. After
     the remove, guest slot 0 and slots 1-3 report not connected. On re-add,
     any reported player index (-1, 0, 1, 3, 7) gets physical slot 0 and
     guest slot 0 follows it. A second cycle behaves the same.
   - With two pads, removing the active pad hands slot 0 to the remaining
     pad. The re-added pad gets slot 1.
   - The new log-field helpers: backend names, `XInput#N` kept verbatim, a
     HID path withheld, empty reported as `none`.
   - **Not done: the SDL virtual-joystick fixture from analysis (d).** It is
     not reasonably bounded. SDL is a static library linked into
     `rexruntime.dll` and, separately, into every consumer executable,
     including `unit_tests.exe`. A virtual joystick attached from the test
     would therefore live in a different SDL instance from the one
     `SDLInputDriver` uses. Making it work would need the driver source and
     its cvars compiled into the test executable, on top of the
     `attached_window_` seam. The SDL patch itself bypasses virtual
     joysticks anyway.

## Owner manual repro (non-destructive, no saves touched)

The candidate must be staged by the primary agent first, with the normal
signing and staging flow. Search the session log for `OnControllerDeviceAdded`
and `SDL gamepad removed`.

1. Close other controller tools (Steam Big Picture, DS4Windows). Keep only
   the 8BitDo dongle plugged in, then start the patched build.
2. In a menu, switch the pad off for 10 s, then on again. Expected, within
   about 1 s in the log:
   - `SDL gamepad removed from physical slot 0`
   - then `OnControllerDeviceAdded: ... Instance(<new id>), Backend(xinput), Path("XInput#M")`
   - then `SDL_ACTIVE_CONTROLLER ... reason=first-connected`
   - then input works. Press F10 for the controller-matrix/input-slot audit.
3. Repeat with the pad left off for 30 s, which is past SDL's 2 s retry
   window.
4. Unplug the dongle for 5 s, then plug it back in. Expect the same
   remove/add pattern.
5. Optional: at the same time, run this read-only XInput index monitor in
   PowerShell to correlate Windows XInput indices with the SDL log:
   ```powershell
   Add-Type -Namespace X -Name I -MemberDefinition '[DllImport("xinput1_4.dll")] public static extern int XInputGetCapabilities(int u,int f,byte[] c);'
   while ($true) { $m = 0..3 | % { if ([X.I]::XInputGetCapabilities($_,1,(New-Object byte[] 20)) -eq 0) { $_ } }
     "{0:HH:mm:ss.fff} xinput users: {1}" -f (Get-Date), ($m -join ',') ; Start-Sleep -Milliseconds 500 }
   ```
   - If the monitor shows an index appear or change and the patched build
     logs a matching add within about 1 s, the fix works for cause 1/2.
   - If the monitor shows no index at all, that is cause 3. Retry once with
     `--hid_sdl_rawinput=true`, which is experimental. Expect
     `Backend(rawinput)`, possibly merged triggers or no rumble, and re-check
     the T300 wheel separately.
   - If the build adds the pad but the game ignores it, that is cause 4. The
     F10 audit should then show guest `GetState` returning success with live
     buttons.

## Limits and follow-ups

- **Nothing is physically confirmed.** Units and builds pass, but whether
  this fixes the owner's 8BitDo reconnect is unknown until the owner repro
  runs. The poll only helps when Windows assigns an XInput index (causes
  1/2). It cannot help with cause 3 (no index) or cause 4 (the guest ignores
  the pad).
- **Upstream divergence.** This is a vendored SDL patch in the SDK fork, and
  the SDL commit exists only in `private/l39-sdk-src`. To publish it, record
  it in the SDK patch list in `docs/rexglue-sdk.md`, and either host the SDL
  commit (a fork branch) or carry it as a patch. After owner confirmation,
  consider an upstream SDL report or PR, with a read-only duplicate search
  first as AGENTS.md requires. Moving the project submodule pin would also
  make `MCLA_REXGLUE_VERSION` and the presets change to the new package
  version.
- **Runtime cost.** Four `XInputGetCapabilities` calls per second inside
  `SDL_LockJoysticks`, on the thread that pumps SDL. With no device change
  there is no extra enumeration. A flapping link produces real remove/add
  pairs, at most about one per second.
- **Spark.** Spark was not used. The work was one coherent source edit plus
  deterministic builds and tests, and no bounded extraction or triage
  remained that would justify offloading.
- **Observation for M9-009, not verified.** Since M9-009, `mcla.exe` contains
  a second statically linked SDL (its joystick strings are absent from l38's
  `mcla.exe`). The host's cursor auto-hide event watch is registered in that
  copy. Whether that copy is the one that pumps window events was not
  checked here. It does not affect KI-040, because the input driver uses the
  SDL inside `rexruntime.dll`, which is patched.
