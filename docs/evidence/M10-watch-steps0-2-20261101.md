## Step 0: census

### Cost

Every census counter is a plain increment or an rdtsc pair around an existing call:
- per protection call (arm and disarm): 2 rdtsc and 3 relaxed atomic adds (the call itself costs
  0.6 us on the PC, 12.9 us on the Deck);
- per arm walk (each `MakeRangeValid` walks the three physical aliases): 2 rdtsc, 2 atomic adds;
- per handled write fault: 1 `GetCurrentThreadId`, 4 atomic adds;
- per `RequestRange(s)` on the command processor thread: one thread-id compare and 2-3 plain
  increments (fast path), plus a few per upload range (slow path);
- per CPU `MakeRangeValid` (about 1,000-1,200 per frame): the step 2 shadow at 16 and 64 pages,
  two constant-time bit scans per cap plus a bitmap test/set (well under 100 cycles);
- per frame: one global-lock acquisition and a 2,048-byte history shift;
- per minute / F10: the report (a 2,048-block scan under the global lock).
No part needed a second switch; only the probes (which run real protect calls and faults) are
behind `memory_watch_probes`.

### Line format

One line per pacing minute (`kind=minute reason=minute`, the window then restarts) and per F10
mark (`kind=mark reason=<f10 tag>`, the current minute so far, not reset), D3D12 only (the Vulkan
command processor has no pacing minute; the memory-side counters still run there). Field groups,
in order:

| Fields | Meaning / how to read |
|---|---|
| `frame frames secs tsc_mhz` | window end frame, frames counted, wall seconds, TSC rate used for all `_ms` fields |
| `census bridge ahead` | switch state at report time (1/1/16 etc.) |
| `arm_calls arm_ms arm_pages`, same for `disarm_` | protection calls, rdtsc time inside the calls, pages covered. Divide by `frames` for per-frame. `arm_ms/arm_calls` = us per call (Deck l56 12.9, PC 0.63) |
| `arm_calls_by_pages=1:a,2_4:b,5_16:c,17_64:d,65p:e` and `arm_ms_by_pages` | the same split by pages per call; same for `disarm_` |
| `arm_hold_ms arm_walks` | global critical region held by the arm walks (lock acquired to walk end, page loop plus protect calls); `arm_ms` is the protect part of it |
| `disarm_hold_ms disarm_walks` | the disarm walk inside the fault handler (lock held by the handler). All watch protection calls are made with the global lock held, so `arm_ms + disarm_ms` is the lock hold inside protect calls |
| `bridged_gaps bridged_pages` | step 1 on: gaps actually bridged (= disarm calls saved) |
| `bridge_shadow_saved_calls bridge_shadow_pages` | step 1 off: disarm calls bridging would have saved (projection; compare with `disarm_calls`) |
| `gap_lock_misses` | disarm walks whose gap classification missed the heap try-lock (those keep the legacy split) |
| `faults_<cp/render/other> fault_ms_ fault_query_ms_ fault_lock_wait_ms_` | handled non-MMIO write faults by faulting thread (CP thread, the guest thread that calls VdSwap, other), our handler time (excludes the OS/Wine dispatch before the handler), `VirtualQuery` time and global-lock wait inside it |
| `src_<vb/ib/tex/resolve/memexport/gpuwritten/other>=req:,fast:,up:,up_kb:,valid:,arms:,arm_ms:` | per request source: `RequestRange(s)` calls, all-valid fast-path hits, upload runs, upload KiB, `MakeRangeValid` calls, arm protection calls and their time. `gpuwritten` is `RangeWrittenByGpu`. Source is set by the caller (vertex fetch and memexport in the D3D12 command processor, index buffers in the primitive processor, the two texture-cache batches, the resolve destination in the D3D12 render-target cache); anything else is `other`. Counted on the CP thread only |
| `hot_blocks=h8:,h4_7:,h1_3:` | 256 KiB blocks by the number of the last 8 closed frames in which a CPU write fault invalidated them |
| `hot_blocks_tex`, `hot_blocks_gpu` | of those, blocks with a texture/range watch overlapping them / with GPU-written pages (step 3 eligibility: hot, no watch, no GPU pages) |
| `cpu_faults by_hot_faults=h8:,h4_7:,h1_3:,h0:` | CPU write-fault invalidations (the non-exact callback) by the block's class when the fault happened |
| `by_hot_requests by_hot_fast by_hot_uploads by_hot_upload_pages by_hot_arms` | the same split of slow-path requests, fast-path hits, upload runs, upload pages and arm calls (class of the first page's block) |
| `ahead_shadow16=saved_uploads:,saved_pages:,saved_arms:,ext_pages:` and `ahead_shadow64` | step 2 projection (only while `ahead=0`): uploads whose pages an upload-ahead would already have uploaded, their pages and arm calls (= arm calls saved), and the extra pages the extension would add. Net extra upload = `ext_pages - saved_pages` |
| `ahead_extended_runs ahead_extra_pages ahead_lock_misses` | step 2 on: runs extended, pages added, runs left exact because the physical-heap try-lock missed |

Probe line (`kind=probe`, with `memory_watch_probes=true`, after the mark line): `tsc_mhz`
(calibrated over 20 ms), `wine=0|1`, `protect_us_private` and `protect_us_section` (average us per
`VirtualProtect` over 1,000 read-only/read-write round trips on a private page and on the reserved
last page `0x1FFFF000` of the guest physical section view, which the guest cannot allocate; left
read-write), `fault_us_first/min/max` over 8 deliberate write faults on a private read-only page
(rdtsc around the store: hardware fault, OS or Wine signal and exception dispatch, the VEH chain and
our probe handler's `VirtualProtect`), `fault_handler_protect_us` (that last part), `maps_lines`
(Wine only: line count of `Z:\proc\self\maps`, the VMA count; -1 elsewhere or unreadable).

Comparing `protect_us_private` against `protect_us_section` and against the in-game
`arm_ms/arm_calls` separates the Wine API cost, the shared-section/VMA cost and the in-game
contention/preemption share (design section 2); `fault_us_*` minus `fault_handler_protect_us`
is the fault dispatch cost the handler timers never see.

## Step 1: disarm safe-gap bridging (`memory_watch_disarm_bridge_safe_gaps`)

In `PhysicalHeap::TriggerCallbacks` (the write-fault disarm), each system page of the widened
window is classified:
- **disarm**: watched and guest read-write (the legacy loop unprotects exactly these);
- **safe gap**: unwatched, committed and guest read-write, read under the existing non-blocking
  alias heap-mutex try-lock. On this alias such a page is host read-write already, so a
  read-write call over it is a no-op;
- **barrier**: everything else, and every unwatched page when the try-lock missed (its state is
  then not known).

`watch_census::DisarmRunBuilder` emits one read-write call per run of disarm pages, joining runs
across gaps made only of safe pages; leading and trailing gap pages are never included; a barrier
ends the run. With the switch off the legacy loop runs unchanged and the same builder only counts
(`bridge_shadow_*`). The page-flag bits, valid bits, invalidation callbacks and watches are
unchanged; only the number and span of read-write calls changes. `watch_disarm_safe_gap_splits`
(F10 state) counts only legacy-mode splits; with bridging on, use `bridged_gaps`.

Why no page of unknown state is touched: a gap page joins a run only when its own metadata was
read under the heap try-lock and shows committed + guest read-write + not watched; guest read-only,
no-access, decommitted and released pages are barriers, and the try-lock prevents a concurrent
protect/alloc/free from changing that metadata during the walk (the global lock, held by the
fault handler, prevents a concurrent arm).

## Step 2: upload-ahead (`shared_memory_upload_ahead_pages` = 0 / 16 / 64)

In `SharedMemory::RequestRanges`, under the global lock, after the exact invalid runs are built:
each run shorter than the cap is extended by `watch_census::ExtendUploadRun` forward (inside the
block of its last page) then backward (inside the block of its first page) over contiguous pages
that are:
- not valid and not GPU-written (resolve/memexport data is never re-uploaded from CPU memory),
- committed with read-write protection in the canonical physical heap (so the arm will actually
  watch them; a page that would stay unwatched while marked valid could go stale). This is read
  with a try-lock on the physical heap mutex; a miss leaves the run exact
  (`ahead_lock_misses`),
- not past the neighbouring runs of the same request (no overlap; touching runs are merged).

The total run length stays at or below the cap (16 or 64 pages = 64 or 256 KiB); a run never
shrinks; nothing crosses its 256 KiB block. The extended run goes through the unchanged
`UploadRanges`: `MakeRangeValid` (valid bits, then the arm) before the copy, so every added page is
protected before it is copied. Sparse host GPU memory: the 256 KiB block lies inside the 4 MiB
allocation already ensured for the requested page. Applies to all request sources and to both
backends (base `SharedMemory`).

| `shared_memory_upload_ahead_64=true` | graphics plugin | writes `shared_memory_upload_ahead_pages=64`; `=false` writes nothing |

The parser was not extended to integer values: it stays strict `name=true|false`, and the integer
cvar needs the command line for any other value. Both upload-ahead keys true in one file is a
conflict: neither is applied and the later line is logged as "conflicting upload-ahead keys". The
apply loop now writes a key's target cvar (`KeyInfo::cvar`, default the key's own name) with the
key's text for the value, and logs `MCLA dev override: shared_memory_upload_ahead_64=true
(shared_memory_upload_ahead_pages=64)`. A command-line or config value of the target cvar still
wins (logged as before).

## Risks

- **Census overhead**: small by construction (above), but on by default in this SDK; arm C0 vs C1
  measures it. The probes cost a visible hitch at the mark and are off by default.
- **Step 1**: a wrong gap classification would make a guest read-only page writable; the
  classification requires committed + guest RW + unwatched read under the try-lock, and unknown
  pages are barriers (tests cover RO, no-access, decommitted and lock-miss gaps). Pages whose notify
  bit was cleared by the `unprotect=false` path (guest `Protect`) before `BaseHeap::Protect`
  updates the host can be bridged to RW while their guest metadata still says RW; the following
  `BaseHeap::Protect` then sets the final protection, so the end state is unchanged.
- **Step 2**: more upload bytes (worst case the whole invalidated block per fault) and upload-pool
  growth; pages uploaded ahead that the guest is still writing fault again sooner (step 3
  candidates). Extended pages become valid and watched; pages that would not be watched are
  excluded by the physical-heap check, but that check reads the canonical physical heap, not the
  alias heaps: a page committed RW there but read-only in an alias would be marked valid without a
  watch in that alias (the same exposure as an exact request of that page today).
- **Shadow accuracy**: the step 2 shadow does not apply the physical-heap writable check and works
  per upload chunk (a run split by the upload pool can count its second chunk as covered), so it
  slightly overstates savings; `ahead_*` counters of the real arm are authoritative.
- **Attribution**: request sources are known for the D3D12 call sites listed above; Vulkan call
  sites are not annotated (`other`) and Vulkan writes no `MCLA_WATCH` line. Render-thread
  identity comes from VdSwap, so faults before the first swap count as `other`.
- **Lock**: protect calls stay inside the global lock (step 4 not done); step 2's try-lock and
  step 1's existing try-lock never block under it.
- Correctness of all steps still needs the owner A/B; nothing here is a physical PASS.
