# l97 owner-internal build: low latency replaces strict (arms), superset of l96 (2026-11-13)

Owner-internal candidate l97, implemented, built and staged by an Opus subagent for the primary
agent. **It has been built and unit-tested only. It is not signed and has not run in the game, so
there is no physical PASS.** The SDK change is described in
`docs/evidence/M11-l97-sdk-20261113.md`. l97 is a **superset of l96**: every l96 arm is kept with
the same body, so the owner needs only this one build. **No default changed**: the strict frame
lead bound stays default ON (m10 default `d3d12_frame_lead_strict=1`), low latency stays default
OFF; only the arms turn the new behaviour on.

Guardrails:
- Nothing was launched (no `mcla.exe`, no launcher).
- No save, profile, ticket, key or registry entry was written. The arm helpers were dry-run against
  a scratch `LocalAppData`; the real per-user override file was not touched (505 bytes, time stamp
  2026-11-12 21:00, same SHA-256 before and after).
- No git write in the main repository. The only git write was the local SDK commit `6c5792d` on
  `mcla/m11-l97` in `private/l97-sdk-wt`, which is not pushed.
- `private/tools/wait-for-idle-pc.ps1` ran before every build and test command (the gate and l97
  host scripts also run it); every step started on IDLE (the owner was on the Steam Deck).
- **Spark was not used:** deterministic implementation, build and staging work, checked by tests.

## 1. What changed vs l96

**SDK:** new, `6c5792d` = ccac775 + l97 (all three SDK DLLs new): `d3d12_frame_lead_strict_low_latency`
(0 default; 1 = strict off while the Reflex sleep is active, 2 = adaptive), the per-frame
fallback to the configured strict mode, the lead-2 guard (2700 frames / more than 80), the
`MCLA_LEAD_LL` lines and the appended `lead_ll_*` MCLA_READBACK fields; `auto` low-latency mode =
Reflex on NVIDIA, Anti-Lag 2 on AMD only with `d3d12_low_latency_auto_antilag2`, off under Wine.

**Host** (the l97 diff on main `ce6e787`): two keys only (`src/mcla_dev_overrides.h`, l96
conventions; `Phase::kGraphicsPlugin`: the cvar is a rexgpu-xenos cvar, registered when the plugin
loads, hot reload, read at every frame open; `=false` writes nothing; not `overrides_user`):

| key | cvar | value |
|---|---|---|
| `lead_ll_off_when_reflex` | `d3d12_frame_lead_strict_low_latency` (int) | `1` |
| `lead_ll_adaptive_when_reflex` | `d3d12_frame_lead_strict_low_latency` (int) | `2` |

Key count 114 -> 116; conflict pairs 27 -> 28 (the two keys); `kNeverWrittenCvars` 93 -> 94
(`d3d12_frame_lead_strict_low_latency`). The keys act only together with a `low_latency_*` key
that starts Reflex. They write a cvar of their own, so the m10 strict default and its
`frame_lead_strict*` keys are unaffected. An SDK without the l97 cvar (the gate SDK l67) logs the
two keys as unavailable. No other host code change.

## 6. What to read in the owner runs

- Identity first: the l97 build fingerprint in the launch receipt; the arm's `MCLA dev override:`
  lines (`low_latency_auto=true (d3d12_low_latency_mode=auto)`, `lead_ll_off_when_reflex=true
  (d3d12_frame_lead_strict_low_latency=1)`); `MCLA m10 default: d3d12_frame_lead_strict=1` (the
  configured mode stays strict).
- `MCLA_LOWLAT v=1 kind=init mode=auto vendor=0x10DE backend=reflex result=ok ...`.
- `MCLA_LEAD_LL v=1 kind=state ...`: one inactive line at start (`undecided` / `no_sleep`), then
  `active=1 reason=active ... effective_strict=0`; how many flips per minute, and with which
  reasons (`stale_sleep` around loads is expected); any `kind=guard_trip` line (time, window).
- `MCLA_READBACK` minute lines: `lead_ll_active_frames` vs `lead_ll_fallback_frames`,
  `lead_ll_eff_hist`, `lead_ll_window_lead2_max` (how close the guard came to 80), and as in l96
  `lead2_frames`, `fence_late_f2p`, `lead_strict_waits` (only on fallback frames).
- `MCLA_LOWLAT` minute lines: sleep ms, `spin_ms_est`, `sim_to_present_ms` (l96 reflex-nostrict:
  12.6 ms), against HWiNFO package power and the proc-sampler render-thread CPU.
- pc\dawn-auto: flicker of buildings / ground at 06:00 (trees: KI-079) with the F10 flight ring.
- pc\auto-lever1: as l96 pc\cp-lever1 (`im_memo_mismatch=0`), fps against pc\auto-adaptive.
