## 1. Problem (l84 Deck)

v1 (`raw_timer_hitch_hold`, l83/l84) held a hitch (> 0.1 s) to min(0.1 s, 1.1 x average) with the
rest in the debt, repaid within +-10 % of an average that **excluded** hitches. It removed the
traffic jumps (owner-confirmed; ambient step jumps 414 -> 3), but on the Deck (12 % hitches,
measured mean 66-71 ms, min 18-25 ms) 1.1 x that average (64-73 ms) stayed below the measured
mean, the debt sat at the 1 s cap and 5.6 s of 256 s (2.2 %, up to 6.3 % per dense window) was
dropped.

## 2. Design of v2 (same key `raw_timer_hitch_hold`, `src/mcla_step_smoother.h`)

With the key **off** the code path is unchanged (bit-for-bit equal to the l84 smoother; asserted
against a frozen copy in the test on every replay sequence). The only additions on that path are
counters (`lost_seconds()`), which do not feed back.

With the key **on**, per raw-timer update with measured step `raw` (constants: average weight
w = 0.05, repayment g = 0.02 (the same as off), band c = 0.10, winsor W = 2, slew k = 0.10,
wide debt D = 0.25 s, game clamp 0.1 s, debt cap 1 s, pause P = 0.5 s):

```
first step after a reset: applied = min(raw, 0.1); average = applied;
                          rest -> debt (or -> paused if raw > P)
raw > P (loading pause):  applied = previous applied; paused += raw - applied;
                          average and debt unchanged (the pause is not replayed)
otherwise:
  average += w * (min(raw, W * average) - average)        # hitches included, winsorized
  band     = c * (1 + clamp((debt - D) / D, 0, 1))        # +-10 %, up to +-20 % at 0.5 s debt
  target   = clamp(average + g * debt, (1 - band) * average, (1 + band) * average)
  applied  = clamp(target, (1 - k) * previous, (1 + k) * previous)   # slew limit
  applied  = min(applied, 0.1)                            # the game's own clamp stays the ceiling
  debt    += raw - applied; time above the 1 s cap -> lost
```

In words: the applied step follows an average of the measured steps that now includes the hitches
(each counted at most as 2x the average, so one rare stutter moves it by at most 5 %); it may
change by at most 10 % from one update to the next; the debt is repaid at 2 % per update within
+-10 % of the average (so the catch-up after a stutter is at most ~1.1-1.15x speed), and only
when the debt passes 0.25 s does the band widen (linearly to +-20 % at 0.5 s) so dense hitch bursts
are repaid before the cap. A single step above 0.5 s is a loading pause: the previous step is
applied again and the rest is dropped (counted as `pause`, not as `lost`). Invariant (tested):
applied + debt + lost + paused == measured.

Rejected while simulating: an average of min(raw, 0.1) (the 0.1 s clip makes it underestimate the
Deck mean by ~7 ms per update; max debt 0.7-1.0 at density 12 %), a fixed +-20 % band
(catch-up 1.23-1.28x after a PC stutter), and a higher repayment gain 0.05 (no Deck gain once the
band binds, and the locked-30 step change rose 0.022 -> 0.028 ms per update).

## 4. Timer stats line (A3, append only)

`MCLA timer stats: ...; far N debt X s` gains `; max_ratio R lost Y s pause Z s`:
`max_ratio` = largest applied (after whole-millisecond rounding, i.e. what the game gets)
step-to-step ratio in the window (`StepRange::max_ratio`, unit-tested); `lost` = seconds dropped at
the 1 s debt cap in the window (both arms); `pause` = seconds dropped as loading pauses in the
window (v2 only; 0 with the key off). With the key off a loading pause still shows as `lost` (unchanged
behaviour: 1 s replayed, the rest dropped).
