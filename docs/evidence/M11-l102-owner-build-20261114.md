## 1. What changed vs l101

**Live (F10, wheel, pad, probe) package retention** below `<diagnostics>/live`:

| | l101 (all builds) | l102 owner-internal | l102 volunteer |
|---|---|---|---|
| Count limit | 10 | none | 50 |
| Byte limit | 256 MiB | none | 768 MiB |
| Free-space floor | none | 2 GiB (new package refused) | none |
| Newest package always kept | yes | yes (nothing is pruned) | yes |
| `.partial` folders older than 24 h removed | yes | yes | yes |

- **Switch:** the CMake option `MCLA_DEV_OVERRIDES` (compile definition `MCLA_DEV_OVERRIDES=1`,
  target-wide for `mcla`) - the same switch that enables the owner override file reader
  (`mcla::dev_overrides::Enabled()`) and marks the measurement build in `mcla_m10_defaults.cpp`.
  `mcla_diagnostics.cpp` reads the macro (default 0) and selects
  `LiveRetentionFor(MCLA_DEV_OVERRIDES != 0)`. Owner builds (gate build and l102) have it ON;
  volunteer builds have it OFF.
- **Pure policy** in `src/mcla_diagnostic_trigger.h`: `LiveRetentionPolicy`,
  `LiveRetentionFor(bool internal_build)`, `ShouldPruneLivePackage(policy, index, retained)`
  (the same newest-first rule as before: index 0 always kept; otherwise pruned when
  `index >= count` or the running total exceeds the byte limit), `LiveFreeSpaceAllowsPackage`,
  `LiveRetentionLogLine`. `PruneDirectories` uses the policy; in unlimited mode it no longer walks
  every package to compute its size (nothing would be pruned).
- **Disk-space safety (owner-internal only):** before a live package is started,
  `std::filesystem::space(<diagnostics>/live)` is read. Below 2 GiB available the package is
  **refused**: nothing is written (no staging folder), no older package is deleted, the snapshot
  status becomes failed, and the log has one line
  `MCLA diagnostics: snapshot refused: <n> MiB free on the diagnostics volume is below the 2048 MiB floor; older packages are kept`.
  A failed free-space query never blocks a report (logged as
  `MCLA diagnostics: free space query failed (...); writing the package`). Chosen as the smallest
  safe behaviour: a package (save copy up to 64 MiB, frame about 8 MiB, optional dump) is never
  started on a nearly full disk, and no partial package is left behind.
- **Start-up line** (once, after the start-up prune):
  `MCLA diagnostics: live report retention count=unlimited bytes=unlimited` (owner-internal) or
  `MCLA diagnostics: live report retention count=50 bytes=805306368` (volunteer).
- **Crash packages unchanged** (`kCrashRetentionCount = 5`, 512 MiB in
  `mcla_crash_handler_win.cpp`). Runtime journal retention unchanged.
- **Launcher:** the post-session report (`src/mcla_session_report.h`, `SessionPackages`) listed
  at most `kMaximumPackages = 64` packages (crash first, then live by name, so with more than 64
  the NEWEST live packages would have been dropped from the session `report.txt` and their
  per-package `report.txt` would not have been completed). Raised to 1024 (a runaway bound only).
  No other launcher, export or import code assumes a package count: `PackageNames` lists every
  folder; the export tool works on one package; `kMaximumPerformanceMinutes = 10` in the export
  policy is minutes, not packages.
- **Tester guide** (`docs/volunteer-tester-guide.txt`): no line mentions the package limit or a
  count of reports (the F10 lines 38-67 and 129-161 describe pressing F10 and the report
  folders only). Nothing to change there.
