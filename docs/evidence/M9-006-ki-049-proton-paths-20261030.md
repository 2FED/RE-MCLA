# M9-006: KI-049 Proton rejects Z: paths - Wine-aware ancestor policy (2026-10-30)

Status: implemented and unit-tested on Windows. **Not verified on the Steam
Deck.** No physical PASS is claimed; the owner check below is required.

## Problem

KI-049 (S1, volunteer blocker on Steam Deck): under Proton the launcher refused
every directory on drive Z: with "directory ancestor is not a normal
non-reparse directory". `OpenDirectory` (src/mcla_launcher_fs_win.cpp) opens
each ancestor with `FILE_FLAG_OPEN_REPARSE_POINT` and refused any
`FILE_ATTRIBUTE_REPARSE_POINT`. Wine reports mount points and Unix symlinks to
directories as reparse points. `Z:\` is Wine's mapping of `/`, and `/` is a
mount point by Wine's own test (`/..` has the same inode as `/`), so the very
first ancestor of every Z: path was refused. `C:` is the prefix's ordinary
`drive_c` directory, which is why only paths inside the prefix worked.

The same guard is used by the host for its own folder
(`src/mcla_build_lease_runtime_win.cpp`, `OpenDirectory(module.parent_path())`)
and by the launcher for its base folder, so a build placed on Z: also failed.

## Wine facts relied on (with confidence)

Source: Wine `dlls/ntdll/unix/file.c`, from memory of upstream Wine 6.x-9.x;
not re-read from source in this task, and Proton's Wine fork may differ.

1. Path-based attribute queries (`get_file_info`): `lstat` symlink whose
   target is a directory -> `FILE_ATTRIBUTE_REPARSE_POINT`; a directory whose
   `st_dev` differs from its parent's, or whose inode equals its parent's
   (the root), is "a mount point" -> `FILE_ATTRIBUTE_REPARSE_POINT`.
   Confidence: high. This matches the owner's observation exactly (Z: refused,
   C: accepted).
2. Handle-based queries (`fd_get_file_info`): the mount-point reparse bit is
   reported only when the handle was opened with `FILE_OPEN_REPARSE_POINT`.
   Confidence: medium. The implementation does not depend on it: when the
   followed handle still reports the reparse bit, only its directory bit is
   used.
3. Reparse tags: Wine may return 0 from `FileAttributeTagInfo`; newer Wine
   builds and wine-staging expose Unix symlinks with
   `IO_REPARSE_TAG_LX_SYMLINK` (0xA000001D) or other tags through
   `FSCTL_GET_REPARSE_POINT`. Confidence: low. The tag is used only for the
   foreign-drive-letter case (below); the common Z: case does not need it.
4. `GetFinalPathNameByHandleW(FILE_NAME_NORMALIZED | VOLUME_NAME_DOS)` returns
   a `\\?\X:\...` DOS path for a Unix path under a drive mapping (Z: maps `/`),
   with symlinks resolved. Confidence: medium-high.
5. `GetDriveTypeW("Z:\")` returns `DRIVE_FIXED` on the Deck. Confidence: high
   (the reported failure was the later reparse check, not the drive check).
   A removable drive letter given by Wine's mount manager to an SD card is
   possible but unconfirmed.
6. Detection: Wine's ntdll exports `wine_get_version`; real Windows does not.
   This is the project's existing test (former `RunningUnderWine` in
   src/mcla_texture_budget_win.cpp). Confidence: high.

## Policy as implemented

- Real Windows: unchanged. Any reparse ancestor is refused with the original
  message; only `DRIVE_FIXED` drives.
- Wine/Proton (`wine_get_version` present): an ancestor with the reparse bit is
  re-opened **without** `FILE_FLAG_OPEN_REPARSE_POINT` (followed). It is
  accepted when the followed object is a directory and either
  - its final path keeps the requested drive letter (`Z:\`, SteamOS mount
    points, `/home` symlinks: verdict "same drive"), or
  - its final path is on another letter and the reparse tag is one of
    LX_SYMLINK / SYMLINK / MOUNT_POINT (verdict "Unix link tag").
  Otherwise it is refused ("directory ancestor is a Wine reparse point whose
  target is not an accepted directory"): dangling links, links to files, and a
  foreign drive without a known tag.
- On acceptance the link handle and the followed directory handle are both
  held, and both identities are recorded (the target's identity is the one
  compared by `CompareDisjoint` and by the canonical identity check). Because
  symlink resolution changes the final path, the existing canonical re-walk
  then holds the complete resolved chain, which is the path every later
  operation uses.
- Under Wine `DRIVE_REMOVABLE` is accepted besides `DRIVE_FIXED`, both for the
  requested path and for the canonical path.
- Files are never relaxed: `ReadFile`, `AtomicWrite` and `AcquireWriterLock`
  still require a regular, non-reparse, non-device, single-link file
  (`platform::RegularFileAttributes`, identical semantics to before).
- Every acceptance is recorded once per path per process:
  `OutputDebugStringW("MCLA launcher: Proton: accepted symlink ancestor <path>
  (same drive|Unix link tag, tag 0x........|none)")`, visible in a Proton log
  with `PROTON_LOG=1`, and `fs::WineAcceptedAncestors()`. CHECK SETUP appends
  " Proton: accepted symlink ancestor <path>[, <path>, <path>] (+N more)." to
  the status line (empty on Windows).
- Not written into `capabilities.txt` or `launch-receipt.txt`: those are
  byte-for-byte reproducible records checked by the controller and capability
  tests, and an environment-dependent list would break that. Status and debug
  log only.
- Guard contracts (`DirectoryGuard`, `WriterLock`, `CompareDisjoint`) are
  unchanged; the header gains one free function, `WineAcceptedAncestors()`.

### Host and crash handler

- Host managed-config check (src/mcla_app.cpp near line 1115): checks the file
  itself (must be a regular, single-link, non-reparse sentinel) and walks no
  ancestors. Policy item (c) keeps that file rule under Wine, so no change. The
  host's own folder guard goes through `fs::OpenDirectory` and receives the
  new policy.
- Crash handler (`IsReparsePoint` in src/mcla_crash_handler_win.cpp) checks
  only entries inside the save/diagnostics trees while copying or pruning,
  never ancestors of the configured roots. Refusing a link inside those trees
  is the intended non-ancestor rule on every platform, so no change.
- `src/mcla_host_platform_win.h` is the shared detection helper;
  src/mcla_texture_budget_win.cpp now calls it instead of its own copy. The
  crash handler needed no detection.

## Limits and risks

- Wine facts 2-4 are from memory, not re-read; the Deck run is the test.
- The SD card case is the least certain: if Wine gives the card its own drive
  letter and reports no tag, the ancestor is refused with the new Wine message.
- The diagnostic image helper (`SafeHelper` in
  src/mcla_diagnostic_image_client_win.cpp) and `mcla_diagnostics.cpp` keep
  their own reparse checks; the F10 image helper still refuses Z: ancestors.
  The image path is not part of the volunteer start path; not changed here.
- The host's managed routing uses `fs::OpenDirectory` only for its own folder;
  other host-side directory checks were not exercised under Wine.
- The acceptance record is per process and capped at 256 paths.
- DGX Spark: not used. The task is a small, security-relevant code change
  whose validation is the build and tests; no bounded extraction or log triage
  was suitable for offload.
