# l103 on the integrated Radeon 860M: Anti-Lag 2 A-B-A by feel (2026-11-15)

Owner runs on the laptop's AMD Radeon 860M (vendor 0x1002, device 0x1114), l103 (build manifest 082EBEA1), 720p Unlocked, copy profile 68e5, free roam, about 5 minutes per arm. Logs read by the primary agent (small greps only, between runs). Spark not used: five short log reads.

| Run | Arm | Session | fps (minutes) | CP fence wait | Anti-Lag 2 sleep | Owner, steering feel |
|---|---|---|---|---|---|---|
| 0 | amd/default (warm-up) | 3d30b0c4 | 28.8 | 44 % of wall | n/a | not judged |
| 1 | amd/default | cfcb6950 | 25.2-27.0 | 25-56 % | n/a | baseline |
| 2 | amd/antilag2 (strict on) | ff7ba97d | 27.3-28.1 | 26-50 % | init ok; 0.15 ms/frame (p50 0.1 ms) | "a bit better, less jelly" |
| 3 | amd/antilag2-replace-noguard | 553c20e5 | 23.1-28.6 | 2-8 % | 21 ms/frame (p50 20-22 ms) | "about the same as run 2" |
| 4 | amd/default | eb68d035 | 25.8-27.7 | 30-56 % | n/a | "the jelly on micro-corrections is really back" |

Findings:
- The AMD driver accepts Anti-Lag 2 on this integrated GPU: `MCLA_LOWLAT kind=init mode=antilag2 backend=antilag2 result=ok amdxc64_preloaded=1`, `sleeping=1` every minute, no failures.
- The new l103 counting path (`lead_ll_count_antilag2`) works on hardware: `MCLA_LEAD_LL kind=state active=1 reason=active ... effective_strict=0`, active in most frames, `stale_sleep` fallbacks of 10-31 frames per driving minute (about 500 during loading minutes), lead2_frames 1-45 per minute.
- The GPU is the limit in every arm (GPU busy 93-95 %); fps is the same in all arms within route noise.
- By feel the A-B-A holds: both Anti-Lag 2 arms are better than both baselines, and the second baseline was run with a warm shader cache, so warm-up does not explain it.
- Not explained: run 2 felt as good as run 3 although our sleep call returned almost immediately there (0.15 ms/frame) and the fence wait stayed high. The driver may shorten its own queue once the interface is active, independent of the sleep we measure. AMD exposes no latency read-back, so this cannot be measured in the log.
- Night flicker (KI-074) could not be judged: KI-081 (world textures flash to white on this adapter from about minute three, in every arm including the baselines) masks it.

Limits: one tester, one short run per arm, 26-28 fps, no latency measurement. Next: the same arms on the RX 6800 XT in the VM for numbers and for a KI-074/KI-081 check at normal fps.
