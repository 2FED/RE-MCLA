# KI-035 warp camera probe, focus logging and state-20 watchdog (l68 host patch, 2026-11-04)

Host-only patch by an Opus subagent for the KI-035 garage-entry freeze ("the game never enters the
garage; the transition shot stays on screen"). Built and unit-tested only; **not run in game**.
Follows the l67 diagnosis in [M10-l67-pc-30min-ki035-20261104.md](M10-l67-pc-30min-ki035-20261104.md):
the mcWarper sat in state 20 with a type-17 cinematic request after "go to garage" from the pause
menu, waiting for its warp camera.

Base: main `1609a74` (tracked `src`, `tests`, `CMakeLists.txt` identical to `41e15f1`). SDK:
`private/l67-sdk-install` (v0.20.0.8 content-logs build of l67). No SDK change.

## 1. What the state-20 handler waits for (generated-code citations)

All citations are `generated/default/mcla_recomp.8.cpp` unless noted. The warper is
`UILogic + 0x51240` (`UILogic = *(0x8286D8D4)`); its update is `sub_8221BE98` (line 10385), called
each UI frame with `r3` = warper and `f1` = dt (`fmr f31,f1`, prologue). The prologue sets
`r28 = 1`, `r26 = 0`. The switch on `+288` sends state 20 to `loc_8221C120` (line 10752):

| `0x8221C130..34` | `lbz r30,3(r11)`, `lbz r29,0(r11)` | request flags +3, +0 |

State 19 (`loc_8221C044`, line 10615) is the same wait for `req+3 == 0` with a different exit
(`+260` accumulator). State 26 (`loc_8221C1F0`) chooses `288 = 19 + (req+3 != 0)` (`0x8221C258..70`),
calls `sub_82219DA0(warper, req+16, req+80, req+96)` and at `0x8221C34C..54` stores
`warper+296 = req+108` (`lwz r10,108(r11)`; `stw r10,296(r31)`).

**The camera object.** `sub_82219DA0` (line 5423) gets the camera from `sub_82219678(request, ...)`
and stores it at `req+108` (`0x82219DE8`) and later at warper+300 (`0x82219EA8`). `sub_82219678`
(line 4316) looks a transition up by name in the UI transition manager (`*(*(0x8286D804)+52)+4`,
`sub_82691650`) and casts it with `sub_823DEDD8` (`__RTDynamicCast`) from type descriptor
`0x827DA9A4` (`.?AVvhsmState@@`) to `0x827DB2F0` (`.?AVUITransition@@`). Names seen in the
branches: `Exiting_Map_GPS_AboveCar`, `..._SouthSideCloseCar`, `..._SharpAngle`. So the warp camera
is a **UITransition** (a vhsm state), not an mcPlayerCamera.

**The getters** (RTTI scan of the decrypted image in RAM, every class with UITransition as a base;
15 vtables, all at complete-object offset 0; listed in `mcla_warp_probe.h`):

| slot | function | body (generated code) | classes |
|---|---|---|---|

| +592 duration | `sub_823ABE90` (`mcla_recomp.22.cpp` 55942) | `lfs f1,76(r3)` | UITransition, _Rotate, _Lerp, _Value, _GPSJump, _LookAtTarget |

camera's own vtable slot, so a derived class that overrides a slot with something else yields
"unknown" (and the watchdog stays idle).

**Active transitions.** `sub_82220980` (line 21949; called from `sub_82219DA0` at `0x82219EB4`
with `r3 = *(*(0x8286D804)+52)`) appends the transition to the manager's active list at
`+0x40850` (pointer array, u16 count at `+0x40854`) and starts it (vfuncs +44, +132, +384, +108,
+64(1), +96(1)). `sub_822247A8` -> `sub_82221DB0` (line 25084) walks that list each frame, asks
vfunc +552 and drops finished entries (+96(0), +64(0), +112, +388); `sub_8221E310` (line 16255)
removes one (also from `Warper_Abort`, `0x8221BC4C`). Whether the camera is in this list is the
"is it being updated" relation visible in the generated code. Which vfunc advances `+96`/`+80`
was not traced; the probe measures whether it advances.

unknown/negative (composite never computed).

## 3. Warp probe log (`--mcla_warp_probe`, default off)

Init-only host cvar; owner builds can turn it on with the dev-override key `mcla_warp_probe=true`
(whitelist in `src/mcla_dev_overrides.h`, Phase::kStartup). Sampled in the existing
`sub_8221BE98` hook after the stock update (guest thread, every UI frame):

- `MCLA_KI035_WARP_STATE v=1 from=<s> to=<s> request=<ptr> type=<n> req0= req3= req7= req9=
  exit276= camera=<ptr> class=<name> ready=<1|0|-1> time=<t> (known|unknown) duration=<d>
  (known|unknown) active_index= active_count= paused= complete=` once per warper state change,
  at most 2,000 per process.
- `MCLA_KI035_WARP_WAIT v=1 state=20 ...` (same fields plus `flags16`) every 5 s while state 20
  lasts, at most 24 per episode.

The existing `MCLA_KI026_WARPER_STATE` line (`--mcla_ki026_probe`) is unchanged and independent.

## 5. State-20 watchdog (`--mcla_warp_watchdog_seconds`, default 0 = off)

Init-only int cvar (0..600 s). Owner builds: dev-override bool key `mcla_warp_watchdog=true` writes
15 (`=false` writes nothing). Rule (pure state machine `mcla::warp::Watchdog`, unit-tested):

- Acts only when a sample is complete (every read of warper, request, camera, vtable and fields
  succeeded), the state is **20**, request and camera are non-zero, and the camera time is known
  (one of the two plain time getters) and not NaN. Anything else resets the episode.
- An episode starts on entering state 20 or when the request or camera pointer changes in state 20.
  "Frozen since" restarts whenever the time exceeds its episode maximum, and while the simulation
  pause manager is paused (`pm+4 && !pm+10`).
- It fires once per episode when the time has not increased for the limit (15 s in owner builds).
  Before writing, it re-checks state == 20 and that `*(0x8286D8F0)+293`, warper+276 and
  warper+288 are in guest heaps with read and write protection; then it performs exactly the
  handler's own exit at `0x8221C1C4..0x8221C1E0`: `*(0x8286D8F0)+293 = 0`, warper+276 = 1,
  warper+288 = 29. No guest function is called. It logs one WARN:
  `MCLA_KI035_WARP_WATCHDOG v=1 action=finish-state20|refused-unwritable limit_s= frozen_ms=
  request= type= req0= req3= camera= class= ready= time= duration= flags16= active_index=
  active_count= global=`.

The skipped part is only the rest of the zoom-in shot; the next warper frame runs the same path as
a camera that reached its duration. Residual risks: a cinematic that is legitimately static for
15 s with the simulation running would be cut short (none is known; the stock zoom-in advances
every frame); the composite-duration case is not needed because the watchdog keys on time only.

## 8. Owner repro protocol (l68 owner build)

Dev-override file (`%LocalAppData%\MCLA-R-Launcher-v1\mcla-dev-overrides.txt`, ASCII) adds:

```
mcla_warp_probe=true
mcla_warp_watchdog=true
```

Run A (with Alt-Tab), then run B (same without Alt-Tab); MAIN profile, 1080p as on l67 is fine:

1. Free roam, start and finish a race (win as on l67).
2. On the result screen Alt-Tab away for about 2 minutes (run B: wait 2 minutes without Alt-Tab).
3. Return, continue to free roam, open the pause menu, choose "go to garage".
4. If the garage shot freezes: press F10, wait 10 s, press F10 again, wait 20 s. With the watchdog on,
   the game should enter the garage by itself about 15 s after the shot stops moving; press F10 once
   more after that.
5. Repeat the garage trip 2-3 times per run if no freeze.

Expected log lines (full runtime log):

- `MCLA dev override: mcla_warp_probe=true` and `MCLA dev override: mcla_warp_watchdog=true
  (mcla_warp_watchdog_seconds=15)` at startup.
- Run A: `MCLA_WINDOW_EVENT v=1 event=focus-lost ...` then `event=focus-gained` around the
  Alt-Tab (plus `minimized`/`restored` if the window minimizes).
- Each garage trip: `MCLA_KI035_WARP_STATE` lines from 29 through the pre-load states to 26 and 20
  (type=17, req3=1), then 20 -> 29 within a few seconds on a normal entry, with `time` reaching
  `duration`.
- A freeze: `MCLA_KI035_WARP_WAIT` every 5 s with the same `time`, then
  `MCLA_KI035_WARP_WATCHDOG v=1 action=finish-state20 ...` and `MCLA_KI035_WARP_STATE from=20 to=29`.

What a watchdog fire proves: the freeze is the state-20 wait itself (not a host hang or a lost load),
and the logged fields name the failing predicate (`ready=0`, or `time` frozen below `duration`,
with or without `active_index=-1`). If the garage then loads normally, the mitigation works for this
signature. It does not prove the root cause (why the transition stopped advancing); the Alt-Tab A/B
and the active-list index point at it. No fire and no freeze is not evidence either way (the freeze
is intermittent).
