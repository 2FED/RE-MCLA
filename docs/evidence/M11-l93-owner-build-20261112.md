## 1. What changed vs l92

**SDK: unchanged** (`private/l92-sdk-install`, e6d6bd3). The three SDK DLL pins are the l92 ones.

**Host** (the l93 diff on main 3693e01 + docs-only commits, HEAD ca2178a):
- New always-on, read-only `MCLA_TOD v=1` log (first update, one line per real minute, every
  night flag change and warp start / end) and the F10 `time_of_day` block, from a pass-through
  override of the time-of-day update `sub_822F1DB0`.
- New default-off controls (host init-only ints): `mcla_tod_rate` (1 = off; 10, 30, 0 = freeze)
  and `mcla_tod_start_minutes` (0 = off; 270, 330), the latter through a pass-through override of
  the warp start `sub_822F1518` that changes f1 only at the Arcade race preset call (return
  0x8265D61C).
- Design decisions, accepted by the coordinator: one int cvar per group; the rate gate is
  session-wide (after the first Arcade preset warp of the process, until the game closes); the
  start keys replace every preset of that call (Midnight, Dawn, Noon and Dusk).
- Five owner keys (startup phase; `=false` writes nothing; none is `overrides_user`):

| key | cvar | value |
|---|---|---|
| `tod_rate_x10` | `mcla_tod_rate` | 10 |
| `tod_rate_x30` | `mcla_tod_rate` | 30 |
| `tod_freeze` | `mcla_tod_rate` | 0 |
| `tod_start_0430` | `mcla_tod_start_minutes` | 270 |
| `tod_start_0530` | `mcla_tod_start_minutes` | 330 |

- Key count 98 -> 103; conflict pairs 18 -> 22 (the rate group of three, the start pair); the two
  cvars added to `kNeverWrittenCvars` (84 -> 86).

Context for the dawn arms: the owner's l92 pc/lead-strict run on 2026-11-12 (session 568cdc6b,
build 103B9D6F confirmed, key applied) showed no flicker; lead2_frames 0, fence_late_f2p 0, 0
