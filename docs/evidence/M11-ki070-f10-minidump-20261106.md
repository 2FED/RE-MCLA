# M11 KI-070: no live minidump in the default F10 path (2026-11-06)

Status: **implemented and unit-tested as a scratch patch; not applied, not committed, not run in the
game. No physical PASS.** Prepared by an Opus subagent for the primary agent. Nothing was launched
(no `mcla.exe`, no launcher, no game); no save, profile, LocalAppData or registry write; no git
write. Spark: not used (a small deterministic code change; no extraction or log triage worth
offloading).

## 1. Problem (KI-070, F10 minidump freeze)

Every live package asked the out-of-process crash helper (`mcla_crash_handler.exe`) for a live
minidump. The helper calls `MiniDumpWriteDump(MiniDumpNormal | MiniDumpWithThreadInfo |
MiniDumpWithUnloadedModules)`, which suspends every thread of the game for the duration. The l70
Hills session (`M11-ki069-hills-freezes-20261106.md`, section 2) measured stalls of 0.34/0.42/0.62/
0.45 s, each ending at the dump close. A tester pressing F10 to report a freeze therefore added a
second freeze.

## 2. Change

- `src/mcla_diagnostic_trigger.h` (pure policy): `DecideLiveMinidump(reason, switch)` returns
  `kRequiredByReason` for the exact reasons `probe` (startup snapshot probe; diagnostics smoke
  contract), `unexpected-guest-exit` and `hang` (reserved for an explicit hang report; no code
  requests it yet), `kEnabledBySwitch` for any other reason when the switch is on, and
  `kSkippedByDefault` otherwise. User snapshots (reasons `f10`, `wheel-r2`, `wheel-l2`, `pad`, and
  any future unlisted reason) therefore skip the dump by default.
  `LiveMinidumpPolicyName` gives the manifest names `required-by-reason`, `enabled-by-switch`,
  `skipped-by-default`.
- `src/mcla_diagnostics.cpp`:
  - new init-only cvar `mcla_diagnostics_live_minidump` (bool, default false, group
    "MCLA Diagnostics"), read once in `Manager::Start`, logged at startup. Not added to the
    dev-override whitelist (`src/mcla_dev_overrides.h` is owned by the parallel triad patch); it
    can be set on the command line / config like the other diagnostics cvars.
  - `Capture` calls `native::WriteLiveMiniDump` only when the policy says so (and the helper is
    ready, as before).
  - per-step wall times: state provider, frame, process/thread census, state + log tail, save
    (gate + copy + metadata), minidump, publish, total. One INFO line per package:
    `MCLA diagnostics: package timing source=... state_provider_ms=... frame_ms=...
    process_census_ms=... state_and_log_ms=... save_ms=... minidump_ms=... publish_ms=...
    total_ms=... minidump_policy=... game_stall_upper_bound_ms=...`, plus a line right after the
    dump step: `MCLA diagnostics: live minidump policy=... written=... ms=...
    game_stall_upper_bound_ms=...`.
  - the helper reports no suspend/resume times (its IPC carries only a result and a sequence), so
    the stall estimate is the game-side round trip of the dump request, an upper bound of the
    suspension; it is 0 when no dump was requested. The helper IPC was not changed.
- Native crash packages (`mcla_crash_handler_win.cpp`, `crash-private.dmp`) are unchanged and
  always dump.

## 3. What an F10 package contains now

Default (switch off), reasons `f10` / `wheel-r2` / `wheel-l2` / `pad`:

- artifacts: `state.json`, `log-tail.txt`, `save-metadata.json`, `save-files-private.json`,
  `frame.bmp` when captured, `save-private/`, `report.txt`, and `save-copy-skipped.txt` when the
  KI-065 gate skipped the save copy. **No `process-private.dmp`.**
- `manifest.json` `capture`: `"minidump": false`, `"minidump_policy": "skipped-by-default"`,
  `"minidump_error": ""` (other fields unchanged).
- new top-level `manifest.json` object `"timing_ms"`: `state_provider`, `frame`, `process_census`,
  `state_and_log`, `save`, `minidump`, `game_stall_upper_bound` (publish and total are only in the
  log line, because they end after the manifest is written). The package's own `log-tail.txt` is
  copied before these lines are logged; they appear in the session log and in the next package.
- `privacy.private_artifacts` still names `process-private.dmp` (a list of possible private
  artifacts, unchanged).

Switch on: user packages again contain `process-private.dmp`, `"minidump": true`,
`"minidump_policy": "enabled-by-switch"`. Probe / unexpected guest exit / hang packages:
`"minidump_policy": "required-by-reason"` and the dump as before.

- `src/mcla_diagnostic_export_policy.h`: unchanged. It already allows 4-6 artifacts with
  `process-private.dmp` optional, reads only `capture.frame` and ignores other capture/top-level
  keys, so packages without the dump and with the new keys project unchanged.
- `tests/mcla_diagnostic_export_policy_test.cpp`: new fixture block: a manifest with
  `minidump=false`, `minidump_policy=skipped-by-default`, `minidump_error` and `timing_ms` is
  accepted and its projection is byte-for-byte identical to the baseline; the same with the dump
  artifact listed and `enabled-by-switch` also projects byte-for-byte identically.
- `scripts/verify-diagnostics-smoke.ps1` requires a live dump; its live package comes from the
  `probe` reason, which still dumps (`required-by-reason`), so the smoke contract is unchanged.
  `scripts/test-diagnostics-smoke.ps1` source needles (`MiniDumpWriteDump`, dump flags) are in the
  unchanged crash helper. Neither script was run here (they launch `mcla.exe`).

## 6. Risks

- **Freeze reports lose the thread stacks.** A default F10 package for a freeze no longer has the
  native stacks of all threads. `state.json` still has the native thread inventory (ids, names,
  priorities, kernel/user times) and the KI-035 10 s guest-thread sampler still runs per accepted
  snapshot; a stack-level investigation needs the switch on for that session (one 0.3-0.6 s stall
  per package).
- The hang path: the KI-035 warp watchdog (`mcla_ki026_probe.cpp`) does not request a snapshot
  today; the reserved `hang` reason keeps the dump if a hang trigger is added later. Unexpected
  guest exit and the startup probe still dump.
- `game_stall_upper_bound_ms` includes the IPC round trip and the helper's file write after the
  threads resume (FlushFileBuffers/CloseHandle), so it overstates the suspension; it is not a
  measured suspend time.
- A tester build with this change produces smaller packages (no dump file); the launcher's bug
  bundle and the export UI need no change (the dump was never exported).
- Not verified in the game: the absence of the F10 stall must be confirmed by a frame-interval
  trace (as in the KI-069 analysis) on an owner/tester session.
