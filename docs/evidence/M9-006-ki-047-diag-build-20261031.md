## 1. Why a diagnostic build

Two direct 1440p runs on an empty shader store were clean (`pso_count=0` in
the F10 audit windows). The two broken l49 sessions still had pipelines being
created at the capture (`pso_count=29`). So H1 is at most a timing race at car
spawn, and repeating sessions without logging cannot settle it. l50 logs the
events that tell the three hypotheses apart in one session:

- **H1**: a draw of the one-time livery composite is skipped because its
  pipeline is still being created. The resolve then reads back stale render
  target content.
- **H2**: the `some` readback is stale or sparse. It copies from the
  previous ping-pong slot, the read slot is not fenced, and only a cache miss
  or every 4th same-range resolve is copied.
- **H3**: the scaled CPU copy is shifted. It downscales from `copy_dest_base`
  but writes at `written_address` (= `copy_dest_extent_start`).

### What is logged

All lines carry the tag `MCLA_LIVERY_DIAG v=1` and come from the GPU log
category. They contain only frame and draw numbers, guest physical
addresses, sizes, formats, EDRAM tile bases and hashes. There are no guest
memory contents and no paths. The frame number is the command processor's
`frame_current_`. The draw index is the count of IssueDraw calls in the
current guest frame, including copy/resolve calls.

| kind | When | Fields |
| --- | --- | --- |
| `start` / `stop` | The first draw skip or read-back resolve after the cvar changes. | frame, `async_shader_compilation`, `async_pipeline_wait`, readback mode, scale, limits (64 lines/min, 120 quiet frames). |
| `pso_skip` | IssueDraw skips a draw because its pipeline is pending (or failed). Logged once per pipeline until that pipeline has been quiet for 120 frames, at most **64 lines per minute**. | frame, draw, `status=pending|failed`, `pso` (description hash), `vs`, `ps`, `edram_mode`, `pitch`, `msaa`, `rt0_base`, `rt0_fmt`, `cmask` (normalized color mask), `depth_base`, `depth_fmt`, `depth_used`, `vp=WxH` (2x the viewport scale), `scissor_br`, `frame_skips` (skips so far in this frame), `wait` (KI-037 wait cvar). |
| `resolve` | Every resolve on the readback path (`readback_resolve` = fast, some or full) with a non-empty, mapped destination. A line is written when the (address, length) range is new or quiet for 120 frames, **or** when draws into the resolved EDRAM base were skipped since the previous read-back resolve. At most **64 lines per minute**. | frame, draw, `mode`, `scale`, `src=color|depth`, `src_base` (EDRAM tiles), `size=WxH` (guest pixels), `fmt` (copy_dest_format), `base` (copy_dest_base), `extent` (written address = extent start), `len`, **`h3`** (1 if scaled and extent != base), `h3_offset` (extent - base, bytes), `key_fresh`, `miss` (no usable second slot, so a synchronous read), **`decision=now|deferred|skipped`**, `reason` (`copied`, `some_interval` for deferred, or the early-exit reason), **`read=this|prev`** (prev = the CPU copy used the previous same-range resolve's slot), `prev_known_complete` (that slot's submission was known complete), `prev_len_ok`, `prev_age` (submissions since that slot was written; 0 = same open submission; 18446744073709551615 = unknown), `since_copy`, **`skips_since_resolve`**, **`skips_same_base`** (skipped draws whose RT0 color or depth base equals this resolve's source base), `frame_skips`. |
| `minute` | Once a minute, after the `MCLA frame pacing/min` line, which then ends in `; pso_pending_skip_per_minute N`. | `pso_pending_skip_per_minute`, `pso_failed_skip`, `resolves`, `scaled_resolves`, `h3_resolves`, `copies_now`, `copies_deferred`, `copies_skipped`, `reads_prev_slot`, `reads_prev_slot_unfenced`, `resolves_after_skip`, `skip_lines_suppressed`, `resolve_lines_suppressed`. |

The per-minute counts cover every event. The line limits apply only to the
detail lines.

### How to read a broken session

First find the livery resolve. It is a 32bpp color resolve (`fmt` of a
32-bit format) of livery/atlas size, logged with `key_fresh=1` shortly after
the car spawns or Photo Mode opens. Then:

| What you see on that resolve (and in the lines just before it) | Points to |
| --- | --- |
| `skips_same_base>0`, or `pso_skip` lines in the same or previous frame with `rt0_base` = the resolve's `src_base` and a matching viewport size | **H1**: the composite drew with a pipeline missing, and the stale render target was read back. |
| `h3=1` with a non-zero `h3_offset` on the livery resolve (and `minute` `h3_resolves>0`) | **H3**: the CPU copy is shifted by `h3_offset` bytes. |
| `decision=deferred` on the livery-size range, or `read=prev` with `prev_known_complete=0`, `prev_age=0` or `prev_len_ok=0` | **H2**: the guest got no copy, or a copy of an older or unfinished resolve. |
| None of these, `decision=now read=this`, no skips | None of H1-H3 on that resolve. Check whether the livery range was logged at all (suppressed counts in the `minute` line) and whether the composite uses a different path. |

A clean session should show the same livery resolve with `skips_same_base=0`,
`h3=0`, and `decision=now`.

## 5. Limits and risks

- **The launcher cannot turn the cvar on.** A managed launch accepts only the
  55-byte sentinel `managed.toml`, the launcher clears `REX_*` variables, and
  its argument list is fixed. The diagnostics are therefore available only in
  direct runs. The primary's latest note (HEAD `a6c9975`) says every broken
  capture so far came from a launcher session at 1440p/2160p and every
  direct 1440p run was clean. If that variable matters, l50 direct runs may
  never break. Covering launcher sessions would need a host change (for
  example, an owner-internal build that forwards the cvar), which is out of
  this task's scope.
- With `--d3d12_livery_diag=true` the extra work is a hash, a few register
  reads and at most 128 log lines per minute, plus the bookkeeping per skip
  or resolve. This could slightly shift the timing race it observes.
- The livery resolve is identified by size, format and timing, not by name.
  If it repeats a range already seen within 120 frames and no skip went into
  its source base, it is counted but not logged.
- `skips_same_base` compares only RT0 color and depth bases. A composite that
  draws to RT1-3 is visible only through `skips_since_resolve` and the
  `pso_skip` lines.
- `prev_known_complete` uses the last observed completed submission. A slot
  can be complete without being known complete. `prev_age=0` (same open
  submission) is the unambiguous unfenced case.
- The D3D12 glue is not unit-tested (no device seam). Nothing was run on a
  GPU.
- The dev SDK is unpinned (`0.20.0.1-dev.g928f6d3`). l50 is owner-internal
  only and must not be offered to volunteers.
