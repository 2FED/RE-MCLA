Build-verification subagent report, for review by the primary agent. Nothing was launched:
no `mcla.exe`, no `MCLA-Launcher.exe`, no `Launch-MCLA.exe`, no game. Only `rexglue.exe`
(`--version`, `codegen`), the 49 host unit test executables and the fake image helper (started

output outside the build directory, never executed). No save, profile, key or LocalAppData file
was opened (the unit tests create their own synthetic fixtures under `%TEMP%`, as in every
earlier run). No git write command was run in the project repository. The HKCU CMake package
registry was not written (`reg query` before and after byte-identical). Spark: not used
(deterministic clone/build/test gates and byte comparisons that a script answers exactly).

Exit criterion checked: "a clean clone builds the volunteer artifacts" for main after the
KI-035 fix, with the l67 volunteer options (`MCLA_M10_SPEEDUP_DEFAULTS=ON`,
`MCLA_PREWARM_SEED_DEFAULT=ON`, `MCLA_DEV_OVERRIDES=OFF`).

## Why the SDK was not rebuilt

The SDK gitlink is unchanged since l67 (`c63895c`, tag `v0.20.0.8`); the l67 clean clone already
built that exact tag from a fresh clone (`private/l67v-sdk-install`, D3D12 only, ctest 2014/2014,
[M9-001 v0.20.0.8](M9-001-clean-clone-v0.20.0.8-20261103.md)). Rebuilding the same commit with
the same flags would only repeat that result. The install was reused **read-only**, after
checking that it is still that build:

- `rexglue --version` = `0.20.0.8`; `rexglueConfigVersion.cmake` declares `0.20.0.8`;
- `rexglue.exe` `E01FB52E...D423`, `rexruntime.dll` `7695301A...892B`, `rexgpu-xenos.dll`
  `1D081EB3...B862`, `TracyClient.dll` `8BE21387...1A1A`: equal to the l67 SDK phase report
  (`private/l67-clean-clone-sdk-20261103-193456.txt`);
- a SHA-256 manifest of all 1201 files of the install, taken before the clone and again after
  all builds and tests, is identical (`private/l70-work/sdk-install-before.txt`,
  `sdk-install-after.txt`): the l70 work did not modify it.

The l70 clone still fetched the SDK and all nested submodules from GitHub and verified them
against the pin, so the clone and the reused install come from the same commit.
