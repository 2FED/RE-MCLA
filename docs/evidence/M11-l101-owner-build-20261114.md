# l101 owner-internal build: per-draw levers for the PC dips (2026-11-14)

Owner-internal candidate l101, implemented, built and staged by an Opus subagent for the primary
agent (code written while the owner played; every build and test started after the owner had
closed the game). **It has been built and unit-tested only. It is not signed and has not run in
the game, so there is no physical PASS.** l101 builds against a NEW SDK,
`private/l101-sdk-install` (SDK `a49e511` on `mcla/m11-l101`, see
[l101 SDK](M11-l101-sdk-per-draw-levers-20261114.md)); all seven pins are new. l101 is a superset
of l100 for every kept arm (unchanged bodies); `cp-reg` is removed on both platforms until the
new verifier split has been read. Basis:
[l100 PC verify and Reflex analysis](M11-l100-pc-verify-and-reflex-analysis-20261114.md) and
[l100 PC dips](M11-l100-pc-dips-analysis-20261114.md).

Guardrails:
- Nothing was launched (no `mcla.exe`, no launcher). No save, profile, ticket, key or registry
  entry was written. The arm helpers were dry-run against a scratch `LocalAppData`; the real
  per-user override file was not touched (same SHA-256 before and after the dry run).
- No git write in the main repository; the SDK commit is local on `mcla/m11-l101` (not pushed).
- `private/tools/wait-for-idle-pc.ps1` ran before every build and test command (every step
  started on IDLE).
- No l100 file was changed.
- **Spark was not used:** deterministic implementation, build and staging work, checked by
  tests.

## 1. What changed vs l100

**Defaults: no lever changed.** Always on (log / detection only): SDK `MCLA_DIP v=1`
(kind=second while a dip lasts, max 30 per minute; kind=summary; kind=minute), `MCLA_TEXMEMO v=1`
and `MCLA_CP_L101 v=1` per perf-split window plus one kind=config line each, three appended
fields on `MCLA_CP_L100` (`cb_mm_new_size_zero=`, `cb_mm_size_changed_nonzero=`,
`cb_mm_same_size_diff_bytes=`), and the MCLA_HITCH threshold max(35 ms, 1.6 x median) (was
50 ms, 2 x). Formats: the SDK document.

**What shipped vs verify-only:** texture memo v2 (`d3d12_fetch_identity_v2`) shipped, verified by
the existing `d3d12_fetch_identity_verify`; the render-target Update memo
(`d3d12_rt_update_memo`) shipped with `d3d12_rt_update_memo_verify`; the cp-reg verifier split
shipped (counters only); PSO reuse (optional T4) not done; nothing is verify-only.

**Host keys** (3 new, 128 -> 131; conflict pairs unchanged; `kNeverWrittenCvars` 99 -> 102):

| `rt_memo_verify` | graphics plugin | `d3d12_rt_update_memo_verify=true` (SDK; wins over rt_memo) | false |

The memo v2 verify is the existing key `fetch_identity_verify` (`d3d12_fetch_identity_verify`);
no `tex_memo_verify` key was added (a second key for the same cvar). `=false` writes nothing for
the three keys; different cvars, so no conflict pairs. An SDK without the l101 cvars logs the
