### A. `d3d12_readback_read_watch` (bool, default false, GPU/D3D12, hot reload)

The SDK had write watches only (`PhysicalHeap::TriggerCallbacks` asserts `is_write`; data
providers / no-access watches are a TODO). The read watch is a separate, minimal mechanism that
reuses the existing exception path:

- **Arm.** After every guest-memory delivery of a read-back key the command processor calls
  `Memory::ReadWatchDeliver(key, base, length, arm_allowed)`: the resolve-path copy (exempt and
  non-exempt, the copy under the pending-table lock is followed by the arm outside it), the
  fenced-delivery copies (`DeliverCompletedReadbacks`, armed after the table call) and the ensure
  calls (`EnsureRange`, guest thread). Under the global critical region the key's host system
  pages in the three guest-physical virtual aliases (A0000000, C0000000, E0000000; page range math
  of `EnableAccessCallbacks`) are set to no access. The delivery memcpy writes through the
  physical view, which is never protected.
- **Exactness with write watches.** A page is armed only when its host protection (VirtualQuery,
  walked region by region) equals its canonical protection: read-only while the page is
  write-watched (`notify_on_invalidation`), else the guest protection (`ToPageAccess`), no access
  when not committed. Any other page is skipped and counted (`arm_mismatch_pages`), so it is never
  touched or restored. While armed, a write-watch arm or disarm that touches the page sets the
  canonical protection itself (the read watch of that page is lost; the next delivery notices
  the lost no-access with one query and re-arms). Disarm restores the canonical protection
  recomputed at that moment, i.e. exactly what the page would have without the read watch. Pages
  shared by several keys are reference-counted (`ReadWatchPageOwnership`).
- **Fault.** `Memory::AccessViolationCallback` (global lock held, as for write faults) first asks
  `ReadWatchHandleFault`: if the faulting host page is held, it records one hit, disarms every
  armed key holding that page (the hit key: the one whose byte range contains the address; the
  others count as `collateral`), restores the pages and returns handled; the access re-executes.
  A write to an armed page that is also write-watched re-executes into a read-only page and
  faults again into the unchanged write-watch path (texture invalidation unchanged; unit-tested
  with a real invalidation callback).
- **Attribution.** The hit carries: key, guest virtual and physical address, in-range flag,
  read/write, the host PC (new `MMIOHandler::CurrentFaultPc()`, a thread-local set around the
  callback), the guest `lr` from the faulting thread's `ThreadState` context (0 on host threads),
  guest and host thread ids, and the command processor clock (frame, submission) at delivery and
  at the fault (`Memory::ReadWatchSetClock`, at every frame open and submission begin while on).
  **What the SDK can resolve:** recompiled code keeps no guest PC, so the logged `guest_pc` is the
  start of the nearest preceding recompiled function: `Memory::NearestGuestFunction` builds once
  (command processor thread, never in the handler) a host-address-sorted copy of the function
  dispatch table; it is used only when the host PC lies in the main executable. `host_pc` is
  `module+0xRVA` (file name only), which resolves exactly against that module's PDB; `lr` is the
  guest return address of the last call made by the faulting function (best effort).
- **Lines** (command processor, one service per frame open):
  - `MCLA_RB_READ v=1 kind=start|stop frame= line_cap=200 fault_cap=20000`;
  - per hit (at most 200 per minute): `MCLA_RB_READ v=1 key=BASE:LEN addr= phys= in_range=
    write= guest_pc= guest_fn_host_off= host_pc=module+0xRVA lr= thread= host_thread= frame=
    age_frames= age_submissions= collateral=`;
  - per minute: `MCLA_RB_READ v=1 kind=minute frame= on= rb_read_faults= rb_read_writes=
    rb_read_collateral= deliveries= arms= refreshes= suppressed= full= arm_pages= arm_shared_pages=
    arm_mismatch_pages= protect_calls= restore_calls= protect_failures= hits_dropped= lines=
    lines_dropped= armed_keys= keys_hit= top_keys= top_readers=` (top 8 each).
- **Bounds.** One fault per key per delivery; after 20000 faults in a minute no key is armed again
  until the minute ends (deliveries counted as `suppressed`); 1024 keys at once; 256 buffered hits
  between two drains. Switching it off disarms everything (every page back). Off: one cvar read and
  one relaxed atomic load per frame open and per delivery, plus one global-lock counter read per
  minute.

### B. `d3d12_readback_age_inject` (int, default 0, range 0..8, hot reload)

`PlanReadbackResolve` (pure) gains `age_inject_frames`, `age_inject_due_frame` and `frame`; the
command processor sets them only in some mode for non-exempt keys. A due every-4th cadence copy is
held (no guest copy, `cadence` false, the counter stays due, the own GPU copy is still recorded so
elision never makes the later copy a guard miss) until `frame - first_due_frame >= N`; then the
normal cadence copy of the previous slot is made. Any guest copy (own slot, miss, forced, or a
deferred fenced cadence) ends a hold. Nothing waits. Counter `rb_age_injected` (held resolves of the
minute) and `rb_age_inject` (the setting) on every `MCLA_READBACK` minute/mark line. With 0 the plan
is identical (unit-tested, with and without elision).

### C. Occlusion query drain (always-on counters) and `d3d12_occlusion_query_bounded_ms`

- Counters after the l91 fields of every `MCLA_READBACK` minute/mark line: `oq_begin`, `oq_end`,
  `oq_drains` (EndSubmission + wait in `EndGuestOcclusionQuery`), `oq_drain_ms_total`,
  `oq_drain_ms_max`, `oq_fake_results` (fallback results written by EVENT_WRITE_ZPD),
  `oq_bounded_ms`, `oq_timeouts`, `oq_previous`.
- `d3d12_occlusion_query_bounded_ms` (int, default 0 = today's unbounded `CheckSubmissionFence`
  wait; range 0..1000, hot reload). N > 0: the wait goes through `AwaitReadbackSubmissionBounded`
  (fence only, at most N ms). Pure decision `DecideOcclusionQueryResult`: reached -> the GPU result;
  timed out with a previous result of the same guest address -> that result (`oq_previous`);
  otherwise the existing fallback (`query_occlusion_fake_sample_count`). Previous results are kept
  only in bounded mode (map capped at 4096 addresses).

### D. Presenter (KI-076)

- `d3d12_present_stats` (bool, default false, UI/D3D12, hot reload): after every successful
  present, `GetFrameStatistics` is sampled; `MCLA_PRESENT_STATS v=1 kind=start`, then once a minute
  `MCLA_PRESENT_STATS v=1 refresh_hz= tearing= sync_interval= swap_chain_flags= presents=
  displayed= rpf0= rpf1= rpf2= rpf3= rpf4p= multi= skipped= disjoint= stats_failed=
  interval_max_ms= int_bounds_ms=8,12,17,21,26,34,50,100 int_hist=` (refresh from
  `GetContainingOutput` -> `GetMonitorInfoW` -> `EnumDisplaySettingsW(ENUM_CURRENT_SETTINGS)`,
  0 when unknown; `rpfN` = displayed frames that stayed N refreshes, from PresentCount /
  SyncRefreshCount deltas with 32-bit wrap; `DXGI_ERROR_FRAME_STATISTICS_DISJOINT` drops the
  baseline; `int_hist` = CPU present intervals in the 9 buckets). Pure accumulator in
  `rex/ui/present_stats.h`.
- `d3d12_present_sync_interval` (int 0|1, default 0, hot reload): the Present sync interval; with 1
  `DXGI_PRESENT_ALLOW_TEARING` is never passed (DXGI requires interval 0 for it). A change is logged
  once (`kind=sync_interval`).
- **Locked tearing: kept default-off (`mcla_locked_tearing_off`, bool, default false, GPU,
  restart).** The code does show that Unlocked already forces the tearing cvar off unless set
  explicitly (`graphics_system.cpp`, the `mcla_guest_vblank_hz > 0` rule). The same rule for Locked
  was nevertheless not made the default: Locked is the stock mode on the Steam Deck, where the
  tearing flag changes the vkd3d-proton present mode (immediate versus mailbox/FIFO under
  gamescope), so the effect there is not known from the code. With the switch on, Locked
  (`mcla_guest_vblank_hz` 0) turns `d3d12_allow_variable_refresh_rate_and_tearing` off at the same
  point as the Unlocked rule and logs `MCLA locked frame rate: presentation tearing disabled`. Like
  the Unlocked rule it acts on swap chains created after graphics-system setup; the
  `MCLA_PRESENT_STATS` line reports the resulting `tearing=`.

  reset); page ownership and the registry (in-range hit before a page-sharing key, recycling of a
  disarmed key, stable entry pointers, top-N formatting); and three real-fault cases on a real

  foreign protection is never armed.

  full mode untouched, a stale hold releases, the fenced deferral still applies.

- `[l92][present_stats]` (3): interval bucketing, statistics deltas (baseline, 1/2/3/4+ refreshes,
  no new frame, skipped presents, disjoint, failure, 32-bit wrap, minute reset keeps the
  baseline, line text), sync interval and the tearing flag rule.

## 5. Not done / risks

- **Not run in the game.** No physical PASS; the read watch has never faulted on a real guest
  access yet.
- **Read watch risks (diagnostic arm only):** a guest buffer in an armed page that the host passes
  to a Windows system call (file or socket I/O) would make that call fail instead of faulting
  (read-back targets are GPU resolve destinations, so this is not expected); host code running on
  the CP or other host threads that reads an armed page through a guest virtual alias is
  attributed by its host module (`host_pc`), which is still informative; the cost is one page fault
  plus a few VirtualProtect calls per key per delivery (bounded by the 20000-fault minute cap);
  page-table reads during arm and restore use the global lock only, as the existing write-watch
  arm does (a concurrent guest re-protect of the same page is the same accepted race).
  `guest_pc` is a function start, not an instruction address.
- **Age inject** acts on the unfenced cadence copy; under `d3d12_readback_fenced_delivery` it
  holds only the immediate copies (fenced deliveries are made by the completion FIFO).
- **Bounded occlusion queries** are untested in the game; on a timeout the late GPU result is
  discarded.
- **Locked tearing** stays the old behaviour unless `mcla_locked_tearing_off` is set.
