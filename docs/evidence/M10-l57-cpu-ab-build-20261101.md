## 2. Host change: dev-override reader (`MCLA_DEV_OVERRIDES`)

- New `src/mcla_dev_overrides.{h,cpp}`, test `tests/mcla_dev_overrides_test.cpp`
  (`mcla_dev_overrides_test`, 76 checks).
- CMake option `MCLA_DEV_OVERRIDES` (OFF by default; ON only for
  owner-internal measurement builds, **never for volunteer builds**). With it,
  `MCLA_DEV_OVERRIDES=1` is defined for every `mcla` object and `shell32
  ole32` are linked. Without it the reader compiles to nothing (no file is
  read, no log line), and the single-line l55 file read of
  `mcla_readback_sync.cpp` is unchanged (verified by compiling the changed
  objects with the option OFF, both with and without
  `MCLA_READBACK_SYNC_COMPOSITE_DEFAULT`: 0 warnings).
- File: `%LocalAppData%\MCLA-R-Launcher-v1\mcla-dev-overrides.txt` (the l55
  file). Read once, at `OnPostInitLogging`, via
  `SHGetKnownFolderPath(FOLDERID_LocalAppData)` and `CreateFileW` with
  `FILE_FLAG_OPEN_REPARSE_POINT`; only a regular file (no directory, no
  reparse point) of at most **1024 bytes** is read.
- Strict parse (pure, `constexpr`): any byte above 0x7F (including a BOM)
  or more than 1024 bytes rejects the whole file (nothing applied). Lines end
  in LF or CRLF; empty lines and `#` lines are skipped. A line must be exactly
  `name=true` or `name=false` with printable ASCII and no spaces. Names are
  limited to the whitelist:

  | Name | Kind | Applied |
  |---|---|---|
  | `mcla_readback_sync_composite` | host, init-only | startup |
  | `mcla_native_d3d_refcount` | host, init-only | startup (before the guest runs; the override reads it at its first call) |
  | `mcla_native_xapi_interlocked` | host, init-only | startup |
  | `d3d12_wrm_event_wake` | SDK (rexgpu-xenos.dll), hot reload | at graphics-plugin load (the plugin registers it) |
  | `d3d12_replay_batched_wake` | SDK (rexgpu-xenos.dll), hot reload | at graphics-plugin load |

  Malformed lines, unknown names and repeated names (the first line wins) are
  ignored and logged by line number (`MCLA dev overrides: line N ignored:
  malformed ... | unknown name | repeated name ...`); the line content is not
  echoed.
- Apply: each value is written with `rex::cvar::SetFlagByName` unless the cvar
  already holds a non-default value (command line or config file: the
  command line wins), or the cvar is not registered (`... unavailable in this
  build`). Every applied value is logged once:
  `MCLA dev override: name=value`. Other lines: `MCLA dev overrides:
  mcla-dev-overrides.txt not present; build defaults`, `... read: N value(s),
  M line(s) ignored`, `... rejected (...)`, `... set by the command line or
  config (...); file value ... ignored`.
- Limit inherited from l55: a command-line value equal to the cvar default
  (e.g. `--d3d12_wrm_event_wake=false`) is indistinguishable from no value, so
  the file wins over it.
- `mcla_readback_sync.cpp`: in `MCLA_DEV_OVERRIDES` builds it no longer reads
  the file itself; it reports the value the reader applied, so the existing
  lines still read `MCLA readback sync: override file mcla-dev-overrides.txt
  found: true|false (applied)` and a file value is not reported as a
  command-line value. The l55 single-line file is a valid multi-line file.
- Calls: `mcla::dev_overrides::OnStartup()` in `MclaApp::OnPostInitLogging`
  (after the log-category setup), `mcla::dev_overrides::OnGraphicsPluginLoaded()`
  first in `MclaApp::OnPostLoadGraphicsPlugin`. The SDK never calls
  `rex::cvar::FinalizeInit`, so init-only host cvars are writable at startup.
- Tests: whitelist and phases (no other cvar, case and suffix), l55 single
  line, all five keys with CRLF and LF, comments and blank lines, mixed file
  with spaces/unknown/bad value/repeat (line numbers), 16 malformed forms,
  NUL, non-whitelisted SDK cvars, bounded issue list, BOM, non-ASCII in a
  comment, exactly 1024 bytes accepted and 1025 rejected, the apply decision,
  `static_assert` parses. The five arm files written by the scripts were also
  parsed by the production header: 5 values each, 0 ignored lines.

## 5. What each arm toggles and what to read

| Arm | Switch | Counters that must change |
|---|---|---|
| refcount | `mcla_native_d3d_refcount`, `mcla_native_xapi_interlocked` | `MCLA_GUEST_SAMPLE` render thread `F80004E0`: share of `sub_82422160` (6.2% in l53) and `sub_824221D8` about 0 in the ON arm, without the callers (`sub_82417E40`, `sub_82415F78`/`FC0`, `sub_82185D80`, ...) rising by the same amount; `MCLA_PERF_SPLIT` / `MCLA_THREAD_CPU` render-thread work ms per frame (target about -1.0 ms at 720p) |
| wrm | `d3d12_wrm_event_wake` | `MCLA_WRM`: `event_wake=1`, `sleeps=0`, `event_waits` = `event_wakes` + `event_timeouts` with wakes far above timeouts, `stale_wakes` small; `wait_ms` per frame and perf split `wrm_mem` per frame down (target 0.5-1.7 of 1.93 ms); `cp_busy_ms`, `ring_idle_ms` |
| replay | `d3d12_replay_batched_wake` | `MCLA_REPLAY_WAKE`: `batched=1 spin_limit=128 wake_batch=512`; `spin_ms` per frame much lower, `deferred_wakes` > 0, `wakes` lower; perf split `replay_cpu_ms - replay_ms` (worker CPU outside replay, 8-10 ms at 720p) down; `stream_finish_wait_ms` may rise up to about 50 us per submission |
| baseline | all three off | `MCLA_WRM event_wake=0` with `sleeps` close to `waited` (about one episode per frame, mass in `h_1to2ms`, top `mem:1FCA3006`); `MCLA_REPLAY_WAKE batched=0 spin_limit=4096 wake_batch=0`; the generated AddRef/Release in the sampler |
| all | all three on | the union of the above; fps, frame-pacing p99/max and `>34ms`/`>50ms` counts |

Arm check in every log: one `MCLA dev override: name=value` line per switch
(five lines; the three host ones near `MCLA lifecycle: logging ready`, the two
SDK ones after the graphics plugin loads), then `MCLA readback sync: override
file mcla-dev-overrides.txt found: true (applied)`. `MCLA_WRM event_wake=`
and `MCLA_REPLAY_WAKE batched=` in the minute lines confirm the SDK side.
`MCLA WRM event wake: on|off` is logged by the CP thread when it sees the switch change (see the SDK evidence).

## 6. Owner protocol

1. Sign and stage: `private\tools\pwsh\pwsh.exe -NoProfile -File C:\BDU\MCLA-Recomp\private\l57-internal-prepare.ps1`;
   in the launcher set the BENCH-C Build folder to `private\l57-internal\build`
   (Unlocked, RTX 5060, 1280x720 scale 1, vsync on) and press CHECK SETUP.
   l57 has a new fingerprint: run one warm-up session first (cold store).
2. **720p Unlocked, BENCH-C warm, the same route loop every session**
   ([M10-001 route protocol](../M10-001-route-protocol.md)):
   `private\l57-ab-baseline.cmd`, then one session; `private\l57-ab-all.cmd`,
   one session; repeat the pair once (ABAB) if time allows.
3. If **all** beats baseline (fps, render-thread work, CP wait), run the single
   arms, one session each, in this order: `l57-ab-refcount.cmd`,
   `l57-ab-wrm.cmd`, `l57-ab-replay.cmd`.
4. 1440p: one pair (baseline, all) on a warm 1440p bench copy with the l57
   build folder.
5. `private\l57-ab-clear.cmd` at the end. The Deck comes later (no Deck
   package is part of l57).
6. Send the full `runtime-*.log` of every session and say which arm each was
   (the log lines of section 5 confirm it).

## 7. Risks and limits

- Not run: no `MCLA dev override` line has been seen; the SDK switches and the
  native refcount have no physical result yet.
- The override file lives in the launcher's per-user folder; every
  `MCLA_DEV_OVERRIDES` build reads it at each start, so a forgotten arm file
  stays active: run `l57-ab-clear.cmd` when the A/B ends. Volunteer builds
  never read the multi-line keys; an l55 build that meets a multi-line arm
  file logs `override file ... found: invalid (ignored)` and keeps the fix ON.
- A config file (`mcla.toml`) value differing from the default also wins over
  the file (reported as "command line or config").
- The batched replay wake and the event wake are the first in-game runs of
  that SDK code (risks in the SDK evidence: worker lag of up to 511 commands,
  event timeouts if the release flag is not written from an interrupt).
- The refcount arm removes the emulated global lock from seven guest helpers
  (risks in [M10-host-cpu-and-ki-fixes-20261101.md](M10-host-cpu-and-ki-fixes-20261101.md)).
- `private/l57-build` was configured from the scratch tree; rebuilding it
  after the patch is applied should point `$Wt` of `l57_ab_build.ps1` at the
  main checkout (the prefix map makes the objects path-independent).
- Spark was not used: a source change with deterministic tests and builds; no
  bounded extraction or triage job whose validation would be cheaper than
  doing it directly.
