## B. Heap pre-creation (`d3d12_texture_heap_precreate`, default 2, 0..8, restart)

- Initialize creates N heaps into a ready pool; log line
  `D3D12TextureCache: pre-created K of N placed texture heaps (B MB each) in T ms`.
- A new allocator block takes a ready heap first. When the pool runs empty, one heap is created
  ahead on a background thread (`std::async`, CreateHeap is free-threaded). A need that arrives while
  the refill runs waits for it. With no pool and no refill it creates synchronously, as in l79.
- Destructor waits for an in-flight refill.
- `MCLA_TEXHEAP` gains `ready_heaps heaps_from_ready heaps_sync heaps_refilled heap_refill_waits
  heap_refill_wait_us_max`, appended. `heap_create_us_max` now covers synchronous creations only.
- Memory: ready heaps are outside the allocator (`reserved_mb` excludes them). At boot there are
  N x block MB (512 MB on PC at 256 MB blocks). These are consumed by the boot load (l79 PC: 4 heaps
  at load). After that, at most one extra idle heap (256 MB). Not active on the Deck (heaps off).
- Not verified at runtime. The RX 6800 XT check from the l79 decision is still pending.

## C. KI-060 (Wine side)

- Path: `KeDelayExecutionThread_entry` -> `XThread::Delay`. Old behaviour, now `XThread::DelayNative`:
  - a relative delay is truncated to whole ms;
  - below 1 ms: SleepEx(0, alertable), or a yield / Sleep(0);
  - 1-2 ms: Sleep(1).
- `ke_delay_short_sleep_mode` (restart, `.allowed`) applies to relative delays shorter than 2 ms, after
  guest time scaling:
  - `yield`: SwitchToThread. An alertable delay with a queued guest APC still goes native, so the APC
    is delivered.
  - `hires_timer`: the exact delay on a per-thread `CREATE_WAITABLE_TIMER_HIGH_RESOLUTION` timer
    (`rex::thread::HighResolutionSleep`), via WaitForSingleObjectEx, alertable when the guest asked.
    A zero delay stays native, because it drains the host wake callbacks. With no timer it falls back
    to native and counts a fallback.
- `apu_worker_priority` (restart, `.allowed`: normal / above_normal / highest) is applied after
  `Create()` to the **Audio Worker** (`AudioSystem::Setup`, runs the guest audio client callbacks)
  and **XMA Decoder** (`XmaDecoder::Setup`) host threads. `normal` leaves them untouched. Log:
  `KI-060: <thread> host priority above_normal (apu_worker_priority)`.
  - Guest thread priorities stay ignored (`ignore_thread_priorities` default true).
  - SDL's own audio device thread is not touched.
  - Unconfirmed: whether F8000534 is the Audio Worker XHostThread (host threads also get guest handles).
- `MCLA_SLEEP v=1 kind=minute` is emitted from the delay path once a minute (relaxed atomics). Fields:
  - short_sleeps, mode, avg_us (measured), max_us, req_avg_us;
  - zero, alertable, alerted, yields, timers, fallbacks;
  - delays (all KeDelay calls);
  - top_thread (guest handle with the most short sleeps) and top_short.

  Startup line: `KI-060: short guest delays (< 2 ms) mode=...`.
- Risks:
  - hires_timer turns sub-ms delays that used to be yields into real sleeps. That is closer to the
    console, but it changes the timing of polling loops.
  - Whether a Wine/Proton waitable-timer wait is cheaper than its NtDelayExecution is the open
    question the Deck run must answer (via MCLA_SLEEP plus MCLA_THREAD_CPU kernel share for F800068C).
  - yield mode can leave host wake callbacks queued until the next real alertable wait.
