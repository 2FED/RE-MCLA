## Grounded instantaneous CPU lead

Independent offline review, reproduced by primary with CDB and exact bundle
bin images, obtains a coherent PE-unwind chain for thread 508 in F10 #2.
Actual RIP is mcla+0x147A04A, within PE runtime-function 0x1479D30--0x147A25C.
Its guest-function breadcrumb binds the function to 0x82412F98, called by
0x82411E98, and the unwind reaches XThread::Execute through valid own-code
frames. This is NOT an arbitrary stack-word/linker-map match.

The reached guest helper has four iterations of eight db16cyc instructions
before checking shared progress. The old generator emits those hints only as
comments. Thread 508 is an autogenerated host-ID name, not a semantic role.
Its subsystem, producer and proportion of CPU spent polling are unproven.
Four other captured RIPs lie in Wine modules whose matching image/unwind
data is absent: reject their caller chains. Missing guest-object/context dump
memory prevents reading progress counters. Do not treat five F10s as a CPU
sampling profile or claim that 91% CPU is all this loop.

The instruction's dispatch-delay intent and exact opcode are also documented
in the [CBE language intrinsics specification, __db16cyc](https://www.cresco.enea.it/LA1/cresco_sp14_ylichron/CBE-docs/Language_Extensions_for_CBEA_2.5.pdf)
and [binutils' exact hint table](https://sourceware.org/pipermail/binutils/2021-June/116987.html).
These describe the hint, not an x86-equivalent cycle count.

## Narrow correction and review

SDK **v0.17.1.0 / 2c7c99c8f7683279295c45b0278cf91b1f88815e** changes only
the db16cyc builder: emit one `simde_mm_pause()` instead of no statement.
On x86 that becomes PAUSE; other host implementations differ (local SIMDe
uses ISB on ARM). There is no Sleep, OS yield, new ABI, PPC register/memory
mutation, guest-clock scaling, renderer/coherency change or new telemetry.
It is a bounded host spin hint, NOT accurate emulation of 16 Xenon cycles.
Generated guest sources must be regenerated, not manually patched or merely
relinked. Increased polling response latency and no FPS benefit are possible.
CPU utilization may remain high because PAUSE does not deschedule the thread.

Primary plus independent exact-decoder/source/test review finds no blockers.
The old generator fails the new emission regression (0/9 hints), while state
tests correctly remain green even when the hint is absent. Final three PPC
cases cover r31, CR, XER carry, memory, finite-loop branching and adjacent
ordinary/record-form OR semantics. The output test requires exactly nine
calls at exact hint sites and rejects accidental hints on neighboring ORs.
Full all-target RelWithDebInfo, Release and tagged Release pass **1,838
executed / four known BitStream skips / zero failures** (1,842 registered).
SDK AST scan/1 fixture passes. Tests do not prove Deck performance.

Separate read-only Vulkan lead: UpdateBindings rebuilds texture/sampler
descriptors even for unchanged adjacent draws. Safe future reuse must retain
RequestTextures/UseSampler, compare actual post-request values and handle
layout/submission/frame/error lifetimes. It is deliberately NOT changed in
this candidate; reuse frequency/CPU share remains unmeasured.
