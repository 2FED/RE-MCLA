## 2. H3: frame caps - which mechanism

- Already in place: the guest vblank rate `mcla_guest_vblank_hz` (SDK `graphics_system.cpp`, int,
  default 0 = the video mode's 60 Hz, hot). The game presents every second guest vblank, so the cap
  is half the rate; the SDK vblank worker accumulates ticks (exact average, about 1 ms jitter per
  vblank). The launcher's Stock mode is this mechanism at 60 Hz (30 fps), Unlocked writes 240. The
  vblank override is held at 0 during `mcla_guest_vblank_unlock_delay_s` (45 s) and while the SDK's
  UI cap is active (menus stay at 30 fps). It works the same on Reflex, Anti-Lag 2 and off.
- The Reflex `minimumIntervalUs` is hard-coded 0 in the SDK (`d3d12_low_latency.cpp`
  `ReflexBackend::Initialize`), as is the Anti-Lag 2 `maxFPS`; no SDK cvar exists. A driver-side
  limiter would only act while the backend is active (not markers-only, not Wine) and would add a
  second pacing system next to the vblank cap; per the brief it is reported, not added. The only
  host sleep point is the low-latency simulation-start hook (`mcla_raw_timer.cpp`), which is inactive
  with the mode off; no new sleep was added.
- So `fps_cap_40` / `fps_cap_60` / `fps_cap_30` write 80 / 120 / 60 to `mcla_guest_vblank_hz`
  (`fps_cap_40` equals the existing `vblank_hz_80`). The effective cap is logged by the SDK's
  existing line `MCLA guest vblank: <N> Hz (video mode 60 Hz, vsync ...)` at every change and by the
  dev-override line; the MCLA_LOWLAT init / minute lines are SDK lines in rexruntime that do not see
  the graphics cvar, and were **not** changed (their `fps=` shows the result).

## 3. H2: collector at 2x (`src/mcla_guest_tiling.h` / `.cpp`)

`gt::CollectorCount(game_count, enabled, where, scene_count)`: for the collector caller (return
`0x825F494C`) only, with `mcla_guest_collector_2x` on, a game count above 2 becomes 2 while the
count last handed to the scene pass is 1 or 2 (`std::atomic<int>`, -1 before the first scene call);
every other caller and the SD path (scene 4x) are left alone. The MCLA_GTILE line of the collector
then shows `msaa=2 requested_msaa=2 applied=1 where=shadow game_msaa=4`. The game's own tile rule
makes the 960x540 collector surface one tile at 2x. **Visual risk:** the collector's depth / shadow
surfaces have half the samples: coarser shadow edges, more shadow aliasing or flicker (Run 3 by eye
against pc/hidef at the same spot).
