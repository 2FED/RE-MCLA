### Default mechanism and why

- The SDK is not rebuilt, so the switch needs a host write. The established host mechanism for SDK
  switches that need a write is the m10 defaults table (`src/mcla_m10_defaults.h` kDefaults),
  which the owner builds already compile in (`MCLA_M10_SPEEDUP_DEFAULTS=ON` is one of the l69
  owner options). Host-owned switches that became default (`raw_timer_hitch_hold_off`,
  `album_preview_restore_off`) changed the host cvar default instead; SDK defaults that became
  default (steady exemption, fence deferral, blend fix) were changed in the SDK. Neither applies
  here.
- Ordering: `MclaApp::OnPostLoadGraphicsPlugin` runs `dev_overrides::OnGraphicsPluginLoaded()`
  first and `m10_defaults::OnGraphicsPluginLoaded()` last. A `frame_lead_strict_off=true` line
  writes `0` (the SDK default) and records `AppliedValue`; `frame_lead_adaptive=true` writes `2`;
  `frame_lead_strict=true` writes `1`. Each makes `KeyLineWins` true, so the m10 decision is
  `dev_override` and nothing is written. A command-line value other than 0 is `user_set`. The host
  switch `--mcla_m10_speedup_defaults=false` also leaves the bound at the SDK default (0).
- Expected log lines: default `MCLA m10 default: d3d12_frame_lead_strict=1`; off arm
  `MCLA dev override: frame_lead_strict_off=true (d3d12_frame_lead_strict=0)` and
  `MCLA m10 defaults: d3d12_frame_lead_strict left at 0 (dev_override)`.
- Wine/Proton decision: ON on both platforms. The file's Wine-only rule is for switches measured
  net negative on Windows (l63); this one was accepted on Windows. The bound fixes a host-side
  pacing state (the CP two frames ahead of the GPU at frame end) that does not depend on the OS,
  and it costs time only while the GPU is saturated (l91 model: about +14 % frame time when
  GPU-bound). Not yet measured on the Deck, which is often GPU-bound; hence the extra arm
  `deck/strict-off` (the Deck control).
- Volunteer builds (also `MCLA_M10_SPEEDUP_DEFAULTS`) would write it too; with an SDK without the
  cvar (before l91) the decision is `unavailable` and nothing is written.
