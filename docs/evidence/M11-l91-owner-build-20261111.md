## 7. Not done / risks

- **Not committed in the main repository** (the primary commits exactly the s.2 diff). The SDK
  commit is local only and not pushed. `docs/known-issues.md`, `docs/M11-priorities.md`,
  `docs/current-state.md` and README-AI were not updated.
- **Not signed:** no ticket, no `private\l91-internal`, no admission row. The build manifest
  fingerprint the owner will see is therefore not known yet.
- **No runtime:** no PC or Deck run, no physical PASS, no performance numbers.
- **Risks, untested in the game:**
  - Strict removes the CPU/GPU overlap across the frame boundary. The model cost is +14 % frame time
    when GPU bound and +30-35 % when CPU and GPU are evenly loaded. The command processor thread
    waits at frame open, so the guest may stall on ring space or fences sooner.
  - Adaptive is reactive. In the model it stays armed and costs almost the same as strict. It is
    kept as a second arm only.
  - On a timeout (a GPU stall over 100 ms) the bound is skipped for that frame, so some gauge-2
    frames and late fences can remain around long stalls (loads, restarts).
  - The always-on counters add one counter update per frame open. In the adaptive mode they also
    read the fence queue head.
