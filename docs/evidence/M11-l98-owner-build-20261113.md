Owner-internal candidate l98, implemented, built and staged by an Opus subagent for the primary
agent. **It has been built and unit-tested only. It is not signed and has not run in the game, so
there is no physical PASS.** The SDK is **not** rebuilt: l98 builds against
`private/l97-sdk-install` (SDK `6c5792d`) as it is. l98 keeps every l97 arm except the four whose
switches are now defaults (`afnative`, `afprobe`, `cp-lever1` / `cp-lever1-noverify`,
`auto-lever1`); in their place come two controls and one diagnostics arm.

Basis: the owner verdicts on the l96 runs
([l96 Deck analysis](M11-l96-deck-analysis-20261113.md),
[l96 PC analysis](M11-l96-pc-analysis-20261113.md)): `audio_filter_native` default on (Deck engine

28 k, mismatch 0, fallback 0); `cp_draw_packet_tsc` and `cp_fence_poll_interval=64` default on
(Deck packets_other 10.22 -> 7.52 ms per frame, a bit smoother, no artefacts);

### Default mechanisms and why

- **Audio: the host-cvar precedent** (`kHitchHoldDefault` in `src/mcla_step_smoother.h`, control
  `raw_timer_hitch_hold_off`, commit `21cea1e`; `kPreviewRestoreDefault`). The cvar is a host
  init-only bool, so the host default itself changes: every build (owner and volunteer, with or
  without `MCLA_M10_SPEEDUP_DEFAULTS` / `MCLA_DEV_OVERRIDES`) runs the native filters. The cvar
  description says "default on since l98". A command-line `--mcla_audio_filter_native=false`
  also turns it off.
- **Lever 1: the m10 defaults precedent** (l94 `d3d12_frame_lead_strict=1` with
  `frame_lead_strict_off`, [l94 owner build](M11-l94-owner-build-20261112.md)). The two cvars are
  SDK cvars of the graphics plugin; the SDK is not rebuilt, so the host writes them at plugin load
  (`m10_defaults::OnGraphicsPluginLoaded`, after `dev_overrides::OnGraphicsPluginLoaded`). A
  control line writes the SDK default and records `AppliedValue`, so `KeyLineWins` is true and
  the m10 decision is `dev_override` (nothing written). A command-line value is `user_set`; an SDK
  without the l96 cvars (the gate SDK l67) is `unavailable`; `--mcla_m10_speedup_defaults=false`
  leaves both at the SDK default. Both platforms: they remove host clock calls and fence polls,
  which do not depend on the OS (the Wine-only rule is for switches measured net negative on
  Windows); the PC l96 cp-lever1 run showed nothing drawn wrong. Volunteer builds (also
  `MCLA_M10_SPEEDUP_DEFAULTS`) write them too.
- The graphics-plugin summary line now ends with
  `d3d12_frame_lead_strict=<v> cp_draw_packet_tsc=<v> cp_fence_poll_interval=<v>` (the effective
  values); the `mcla_m10_speedup_defaults` description names "CP draw-packet clock and fence poll
  64".

### Audio hook overhead with the default (native on, probe and self-check off)

- New `audio_filter::Lean(native, verify, probe)` = native && !verify && !probe (cached once in a
  static, as the other switches). In this mode:
  - `sub_82146BE0` and `sub_82147738` call the native kernel directly: no clock reads, no MXCSR
    save/restore, no `af::Stats` per call, no merge or mutex. The kernels' own counters go to a
    thread-local sink that is never read.
  - `sub_823EC248` (engine frame) calls the original directly: no frame timing, no lock, no
    per-second line.
  - The only counters are two relaxed atomics, incremented only on a fallback.
- **Fallbacks kept as before:** `Native` returns false (the original runs) when bank A or B is on
  and the buffer argument or its sample pointer is 0; `NativeChannel` returns false when the
  buffer argument is 0, or the count is non-zero and the sample pointer is 0. Both kernels do the
  original's `disableFlushMode` first. `audio_filter_native_ch_off` still keeps `sub_82147738` on
  the recompiled code (lean then passes it straight to the original).
- Log: one line at start-up from `MclaApp::OnPostInitLogging` after the override file and the m10
  start-up defaults: `MCLA_AFILT v=1 kind=config native=1 verify=0 probe=0 ch_off=0 lean=1` (the
  requested prefix plus `ch_off` and `lean`), in every build and every log. No other MCLA_AFILT
  line in the default.
- F10 `"audio_filter"` in the lean mode: `{"version": 1, "probe": false, "native": true,
  "verify": false, "lean": true, "ch_off": false, "fallback": N, "ch_fallback": N}`. With the
  probe or the self-check on (arm `audio-verify`) everything is as in l89-l97 (`kind=start`,
  per-second lines, full F10 block).
