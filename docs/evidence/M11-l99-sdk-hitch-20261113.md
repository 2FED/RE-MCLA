## 2. MCLA_HITCH v=1 (always on)

### Detection (CP thread, `D3D12CommandProcessor::HitchFrameEnd`)

At every frame end in `EndSubmission` (the point where the "MCLA frame pacing/min" interval is
measured) the CP copies `HitchCounters` (about 22 integers: perf-split region ticks, census draw
ticks, ring idle, WAIT_REG_MEM, watch arm, GPU busy, strict wait, Reflex sleep, texture and
pipeline counters, submissions) and pushes the frame interval into a 255-frame ring. The interval
is the existing steady_clock frame-end-to-frame-end interval of the pacing line (no second clock;
on Windows steady_clock is QPC); the region deltas are converted with the TSC rate calibrated
since the processor was created, only for a logged hitch. Only when the interval is above 50 ms is
the median computed (`nth_element` on a copy of the ring); a frame is a hitch when the interval is
above `max(50 ms, 2 x median)` of the previous 255 frames. A hitch line is written only within the
budget of 20 lines per minute; every hitch is counted and published (`PublishHitch`).

Cost per normal frame: the counter copy (one `GetAccessDiagnosticSnapshot` of the memory object,
relaxed atomic loads; one relaxed load of the Reflex sleep total; two relaxed pipeline counters)
and one ring push. Not measured; estimated well under 1 us.

### Event line

`MCLA_HITCH v=1 frame= ms= median_ms= cause_hint= guest_sim_ms= cp_busy_ms= cp_wait_ms=
strict_wait_ms= ll_sleep_ms= fence_wait_ms= wrm_ms= rbsync_ms= stream_finish_ms= upload_ms=
upload_mb= watch_arm_ms= draw_ms= present_ms= gpu_busy_ms= tex_creates= tex_create_ms=
tex_evicts= tex_loads= pso_new= pso_wait_ms= shader_new= im_loads= draws= subm= lead=
vram_over_mb= cause_ms= split= seq=`

All values are deltas over this frame interval (counters at this frame end minus the previous
frame end):

| field | source |
|---|---|
| frame | the CP frame (`frame_current_`) |
| ms / median_ms | the interval / the running median before it |
| guest_sim_ms | CP ring idle (`command_ring_idle_us`): the CP waited for the game to submit |
| wrm_ms | WAIT_REG_MEM waits (register and memory) |
| cp_wait_ms / cp_busy_ms | guest_sim + wrm / ms minus that |
| strict_wait_ms | the `d3d12_frame_lead_strict` and `d3d12_frame_lead_limit` waits (new cumulative counter) |
| fence_wait_ms | perf-split kFenceWait minus strict_wait (the strict waits are kFenceWait regions too) |
| ll_sleep_ms | Reflex / Anti-Lag 2 sleep on the guest thread (pre-sleep + driver), new counter |
| rbsync_ms, stream_finish_ms, upload_ms, present_ms, pso_wait_ms | perf-split regions kReadbackWait, kStreamFinishWait, kUpload, kPresent, kPipelineWait (exclusive) |
| upload_mb | perf-split upload bytes |
| watch_arm_ms | memory watch arming |
| draw_ms | census class draw (every draw packet timed, exclusive of regions) |
| gpu_busy_ms | GPU timestamps resolved during the interval (they lag up to 2 frames) |
| tex_creates, tex_create_ms, tex_evicts, tex_loads | texture churn counters (section 3) |
| pso_new, shader_new | pipeline creations / shader translations attempted (any thread) |
| im_loads | IM_LOAD + IM_LOAD_IMMEDIATE packets |
| draws, subm, lead | draws of the frame, submissions, frames in flight at this frame end |
| vram_over_mb | host usage minus host budget from the host's last sample (`na` without one) |
| cause_ms, split, seq | the winning contributor's ms; 1 when `d3d12_perf_split` is on; the hitch sequence |

The region fields advance only while `d3d12_perf_split` is on (the owner builds default it on);
`split=0` says they are 0. tod_hour and the other game state are in the host's companion line
(section 6): the SDK does not know them, and a host callback into the CP thread was judged less
safe than a polled sequence counter.

### cause_hint (pure `HitchCauseHint`, unit-tested)

The largest of seven non-overlapping contributors, ties to the earlier one:

1. `guest` = max(0, guest_sim_ms - ll_sleep_ms) (the CP is idle while the guest sleeps, so the
   sleep is taken out);
2. `cp_busy` = max(0, cp_busy_ms - (fence + strict + rbsync + present + upload + tex_create +
   pso_wait)): CP work that is none of the others;
3. `gpu` = fence_wait + strict_wait + rbsync + present + wrm (waits for the GPU or the display);
4. `sleep` = ll_sleep_ms;
5. `upload` = upload_ms; 6. `tex` = tex_create_ms; 7. `pso` = pso_wait_ms.

Limits: ring idle and WAIT_REG_MEM are completed-episode totals, so a wait spanning two frames is
charged to the frame where it ends; texture *load* time is not timed separately (it stays in
cp_busy); with the split off the region terms stay in cp_busy.

### Minute line

`MCLA_HITCH v=1 kind=summary count= max_ms= suppressed= logged= frames= median_ms= max_frame=
total= floor_ms=50 factor=2 lines_max=20`, every pacing minute (also with no hitch).

## 3. Texture churn (counters always on; the fix default off)

- Counters (cumulative, CP thread): creates, resource creation us (D3D12), creation failures,
  loads, evictions and their bytes, recreates (a key created again within 30 s of its eviction:
  a 4096-slot direct-mapped table keyed by the XXH3 of the texture key, i.e. guest address,
  format, size and the rest of the key; a collision loses the older entry, so `recreates` is a
  lower bound), min-age stops.
- MCLA_TEXHEAP v=1 kind=minute appends: ` evicts= evict_mb= evict_min_age_s= recreates= hard_mb=
  soft_mb= min_age_ms= min_age_stops= tex_loads= create_failures=` (evict_min_age_s: the youngest
  evicted texture of the minute, `na` when none; hard/soft: effective limits incl. the
  scaled-resolve allowance).
- `texture_cache_min_age_ms` (GPU, int 0..60000, hot reload, default 0): the trim rule moved into
  the pure `DecideTextureEvictStep`; with 0 it is identical to the old loop (tested over a grid
  against a copy of it). With N > 0, above the hard limit the trim stops at a texture used within
  the last N ms (the LRU head, so every later one is younger) unless a texture creation failed in
  the last 2 s (taken as out of memory). Host key `texture_min_age_2000`.
- Host `mcla_texture_hard_margin_mb` (section 6) keeps the hard limit above soft.

## 4. MCLA_VRAM_SDK v=1 (always on, once per minute)

`MCLA_VRAM_SDK v=1 reason=minute budget_mb= usage_mb= over_mb= nonlocal_mb= host_age_s=
tex_heaps_reserved_mb= tex_ready_heaps_mb= tex_used_mb= tex_committed_mb= rt_mb= edram_mb=
scaled_resolve_mb= shared_mem_mb= readback_mb= upload_pool_mb= swapchain_mb=na other_known_mb=
local_known_mb= unaccounted_mb=`

The prefix is `MCLA_VRAM_SDK`, not `MCLA_VRAM`: the host already logs `MCLA_VRAM v=1` with other
fields. The SDK makes no D3D query: budget / usage / non-local come from the host's existing
once-per-second `QueryVideoMemoryInfo` (published through `rex_vram_host_sample`; `na` and
`unaccounted_mb=na` without a sample, e.g. under Wine where the host monitor does not run).
local_known = placed heaps + ready heaps + committed textures (all textures minus the placed
ones) + render targets + EDRAM + scaled-resolve heaps + resident shared memory + scratch /
downscale buffers; read-back and upload pools are system-memory heaps and listed separately.
Render target sizes come from one `GetResourceAllocationInfo` at creation (a CPU-side call); the
swap chain is not visible to the SDK.

## 5. Guard actions (default unchanged)

`d3d12_frame_lead_strict_low_latency_guard_action` (GPU/D3D12, int 0..3, hot reload, default 0)
and `..._guard_rearm_frames` (default 5400, 0 = never):

| action | on a trip | host key |
|---|---|---|
| 0 | the configured mode (strict) for the session: l97, the l97 trip line text unchanged | (none) |
| 1 | frames opened with the sleep active run ADAPTIVE for the session | `lead_ll_guard_adaptive` |
| 2 | the configured mode until rearm_frames clean frames (sleep active, frame-end lead below 2; a lead-2 frame restarts the count), then relaxed again with an empty window (`kind=guard_rearm`) | `lead_ll_guard_rearm` |
| 3 | observe only: never latches; each time the window goes above the threshold is one would-be trip (`lead_ll_guard_would_trip`), the first one writes `kind=guard_would_trip` | `lead_ll_guard_off` |

The stale-sleep fallback (the configured strict mode on any frame without an active sleep) is
unchanged in all actions. Lines: `MCLA_LEAD_LL v=1 kind=guard_trip ... guard_action= trips= (...)`
(actions 1 and 2), `kind=guard_rearm frame= clean_frames= trips= rearms= (relaxed again)`,
`kind=guard_would_trip frame= lead2_in_window= window_filled= guard_frames= guard_lead2= (observe
only; ...)`. MCLA_READBACK minute and mark lines append ` lead_ll_guard_action=
lead_ll_guard_rearm_frames= lead_ll_guard_rearms= lead_ll_guard_would_trip=
lead_ll_guard_trips_total= lead_ll_guard_rearms_total= lead_ll_guard_would_trip_total=`. Unit
test against the l98 soak shape: 90 lead-2 frames per 2700 trip action 0 at the 81st (frame
2400); action 3 writes one would-trip line and never changes a frame's mode.

## 6. Host side (l99 host diff, see `M11-l99-owner-build-20261113.md`)

- `MCLA_HITCH_HOST v=1 seq= frame= ms= tod_hour= paused= warp= pursuit=na missed=`: the
  time-of-day update hook polls `rex_hitch_logged_sequence` (one atomic load per update) and,
  when it moved, reads `rex_hitch_last` and writes one line with the hour, pause and warp of that
  update (`na` when the lighting manager is not plausible). Pursuit state is not cheaply known
  (`na`). One `MCLA_HITCH_HOST v=1 kind=entry sdk_entry=found|absent` line.
- The budget monitor publishes its sample every second (`rex_vram_host_sample`).
- `mcla_texture_hard_margin_mb` (host, init-only, default 0; key `texture_hard_margin_256`): the
  monitor never steps the hard limit below the starting soft limit + margin.
