# KI-076 frame pacing at 60 Hz, and NVIDIA Reflex / AMD Anti-Lag 2 design (2026-11-11)

Read-only design by an Opus subagent (SDK ef72fd1), accepted by the primary agent as a design; the tearing-vs-judder question is unverified until the owner test. Licence: code only from the MIT NVAPI and AMD Anti-Lag 2 SDK headers; the GPL forks and LARecomp are ideas only. Spark not used: source reading.

**Headline.** A torn composite cannot come from our pipeline (the CP writes a free mailbox slot and publishes whole frames; Paint references a published slot on the same queue), and with the flip model and Present(0) without ALLOW_TEARING DXGI flips at vblank; real tearing would need a driver override. What the owner most likely saw at 60 Hz is judder: 45 fps on 60 Hz shows frames for 16.7/16.7/33.3 ms, on 120 Hz 16.7/25/25 ms. Present(1) would not fix that; on 60 Hz only 30 fps is judder-free (Locked). Side finding: Locked starts without the vblank argument and keeps the tearing flag ON, so Locked can really tear at 60 Hz on a display without VRR. Nothing logs refresh rate, present mode or frame statistics. First step: owner A/B without a build (60 Hz: Unlocked vs Locked, PresentMon CSV + a slow-motion clip); then a small diagnostic build (d3d12_present_stats, d3d12_present_sync_interval, tearing flag off in Locked). Reflex / Anti-Lag 2: feasible from the MIT NVAPI and AMD headers (sleep at the game frame-timer hook, markers at frame open / swap / present); the predictive sleep engages exactly when the GPU is the limit, so it may bound the CP lead without the 2-6 fps of our strict wait, as a complement not a replacement; never loaded under Wine; busy-wait CPU cost must be bounded on the 35 W laptop; Reflex ~2-3 days, Anti-Lag 2 ~1 day, markers-only phase first.

# KI-076 (60 Hz pacing / "tearing") design notes + Reflex / Anti-Lag 2 design

Read-only. SDK = private/l91-sdk-wt (l91, ef72fd1). Nothing built or run.

## Code facts
- Swap chain: FLIP_DISCARD, Flags 0 unless d3d12_allow_variable_refresh_rate_and_tearing && dxgi_supports_tearing (d3d12_presenter.cpp:419-426). No waitable object, no SetMaximumFrameLatency (DXGI default 3), no GetFrameStatistics anywhere in src/ui.
- Present(0, RESTART [+ALLOW_TEARING]) (d3d12_presenter.cpp:1176-1178).
- Unlocked (mcla_guest_vblank_hz>0) forces the tearing cvar false unless set explicitly (graphics_system.cpp:186-193). Locked (stock, no --mcla_guest_vblank_hz, mcla_launcher_capabilities.h:267-269) leaves it at the default true: Locked presents WITH ALLOW_TEARING when DXGI supports it.
- Guest vblank: "GPU VSync" thread, Sleep(1 ms) loop, MarkVblank on an interval of 1/refresh (video mode 60 Hz) or 1/mcla_guest_vblank_hz (graphics_system.cpp:209-235). Not phase-locked to the display. Game presents every 2nd vblank: 240 -> 120 cap (Unlocked), 60 -> 30 (Locked), keys vblank_hz_72/80/88 -> 36/40/44 (mcla_dev_overrides.h:390-392, 568-572).
- Who presents: in gameplay without UI drawers, the CP thread itself inside IssueSwap -> RefreshGuestOutput -> PaintAndPresent(false) (presenter.cpp:635-638, mode chosen at presenter.cpp:1335-1342). With UI drawers (overlay/ImGui), the UI thread paints after WaitForUITickFromUIThread, which waits on IDXGIOutput::WaitForVBlank (presenter.cpp:484-486, 1593-1677).
- Display-vblank source already exists: DXGIUITickThread + GetDXGIOutputForMonitor (presenter.cpp:1630-1677).

## Q1 torn composite
- Not possible by construction. Producer: the CP records gamma/FXAA into the writable mailbox slot and calls EndSubmission(true) INSIDE the refresher before publishing (command_processor.cpp:2709-2714); publish is a CAS of acquired/ready (presenter.cpp:592-621); writable is never the acquired or ready slot (presenter.cpp:605-621). Consumer takes a ref under the consumer lock (d3d12_presenter.cpp:605-616) and submits on the same direct queue (d3d12_presenter.cpp:1163; CP 6136), so GPU order = CPU publish order. A freed slot is rewritten only after the paint that read it was already submitted (same thread order, paint ownership exclusive under paint_mode_mutex_, presenter.cpp:626). Whole-frame drop/repeat yes; split no.
- F10 captures the guest-output mailbox slot (CaptureGuestOutput, d3d12_presenter.cpp:205-226), not the back buffer, and only already-presented sequences. So F10 can never show a DXGI/scan-out tear; "no tear line in F10" proves only that the guest image is whole.

## Q2 DXGI behaviour
- Flip model, sync interval 0, no ALLOW_TEARING: composed flip (DWM) shows the newest queued frame at each vblank; independent flip / MPO flips at vblank. Neither tears. Producer 44-50 fps < 60 Hz: nothing dropped; each frame shown for 1 or 2 refreshes.
- Real tearing without ALLOW_TEARING only via driver override: NVCP "Vertical sync = Off" can force immediate flips in independent flip; "Fast" does not tear. G-Sync/VRR: Microsoft requires ALLOW_TEARING + interval 0 for windowed VRR, so Unlocked (flag forced off) most likely runs fixed-refresh even on a VRR monitor (NVIDIA "G-Sync windowed" may still engage; unknown). Locked (flag on) can genuinely tear on a non-VRR display in independent flip.
- Knowable from logs: only "presentation tearing disabled" + F10 "window 2560x1440 fullscreen" + initial swap chain size. Not logged: refresh rate, present mode (composed vs iflip vs MPO), VRR state, present statistics. Present mode is only observable through ETW (PresentMon).

## Q3 perception
- 45 fps on 60 Hz: 3 frames per 4 refreshes, durations 16.7/16.7/33.3 ms (error up to a full 16.7 ms) -> judder, moving edges double/jump; at 120 Hz: 16.7/25/25 (error 8.3 ms) -> much less visible. Matches "visible at 60, not at 120". Real tearing = horizontal split within one refresh.
- Distinguish in one test: PresentMon (free, MIT) CSV: PresentMode, AllowsTearing, MsBetweenDisplayChange (judder histogram). Plus 240 fps phone slow-mo of a vertical edge while panning: tear = split line inside a camera frame; judder = whole image held 2 refreshes then jumps.
- Built-in (proposed d3d12_present_stats, default off): per present QPC interval histogram; GetFrameStatistics every present -> delta SyncRefreshCount per displayed frame (1/2/3/4+), delta PresentCount vs displayed (dropped), GetLastPresentCount; log monitor refresh via EnumDisplaySettings(ENUM_CURRENT_SETTINGS) on MonitorFromWindow and tearing flag; one line per minute "MCLA_PRESENT_STATS v=1 refresh_hz= tearing= presents= displayed= dropped= rpf1= rpf2= rpf3= rpf4p= int_hist=". Insert after d3d12_presenter.cpp:1183.

## Q4 options
(a) Present(1): present is on the CP thread (presenter.cpp:638). Below refresh, displayed cadence is identical to Present(0) in flip model (both flip at the next vblank), so it does not fix judder; it only defeats a driver "VSync off" override (if the driver honours app setting) and adds back-pressure when the 3-deep queue fills (GPU-bound -> CP blocks in Present, like the M8 timebox 11-14 ms/frame block). Above refresh: caps to 60. Cheap (cvar d3d12_present_sync_interval 0|1). Useful only as a tearing rule-out.
(b) Waitable swap chain + latency 1 + vblank driven by WaitForVBlank: medium-large, swap chain flag change, CP waits on waitable; guest timing risk (Deck/Proton). With a 44-50 fps CP-bound producer it can only give 30 (every 2nd refresh) on 60 Hz: no benefit over Locked until the producer reaches 60.
(c) Limiter matched to refresh: on 60 Hz the only judder-free fixed rates are 60 and 30; 60 is unreachable (CP-bound), so 30 = Locked = vblank 60. vblank_hz_72/80/88 (36/40/44) all judder at 60 Hz (fine on 120 Hz: 40 = every 3rd refresh, smooth). Lead bound bonus: 30 cap implies lead <= 1 -> no KI-074 flicker (44 cap already removed it). Remaining Locked imperfection: host timer not phase-locked, Sleep(1 ms) jitter -> occasional 16/50 ms beat; fix later by driving MarkVblank from WaitForVBlank when vblank_hz == display refresh. Also Locked has ALLOW_TEARING -> could tear at 60 Hz on non-VRR; force off there too (one-line change mirroring graphics_system.cpp:188).
(d) Document: Unlocked is for >= 120 Hz or VRR; 60 Hz -> Locked 30. Zero cost.
(e) VRR for Unlocked: allow ALLOW_TEARING when the monitor is VRR (cannot detect reliably via DXGI; user opt-in). 44-50 fps in VRR range = smooth; non-VRR = real tearing.

Recommendation: first A/B with NO build (d+c): on 2560x1440@60: Unlocked default vs Locked 30 vs Unlocked+frame_lead_adaptive, each 3 min same route, PresentMon running, one 240 fps phone clip per arm, NVCP VSync / G-Sync settings noted. Then build: d3d12_present_stats (diag) + d3d12_present_sync_interval (rule-out) + Locked tearing force-off, keys present_stats, present_interval_1. Launcher hint later: "60 Hz display: Locked 30 recommended" (owner said no menu message for now -> docs only).

## Reflex / Anti-Lag 2
- APIs. Reflex (NVAPI, nvapi64.dll via nvapi_QueryInterface, ids from MIT nvapi_interface.h): NvAPI_D3D_SetSleepMode(device, {bLowLatencyMode, bLowLatencyBoost, minimumIntervalUs}), NvAPI_D3D_Sleep(device) once per frame before input sampling (driver delays the thread so the frame's GPU work arrives as the GPU frees -> render queue ~0), NvAPI_D3D_SetLatencyMarker(device, {frameID, markerType SIMULATION_START/END, RENDERSUBMIT_START/END, PRESENT_START/END, INPUT_SAMPLE}), NvAPI_D3D_GetLatency (64-frame report), NvAPI_D3D_GetSleepStatus. Boost = keep clocks high (more power: bad on 35 W shared cap). Anti-Lag 2 (MIT ffx_antilag2_dx12.h, amdxc64.dll): AMD::AntiLag2DX12::Initialize(&ctx, device), Update(&ctx, enable, maxFPS) once per frame just before input sampling (it sleeps inside), DeInitialize; frame-gen markers (MarkEndOfFrameRendering, SetFrameGenFrameType) unused (no frame gen).
- Our points: sim start / input sample = raw timer hook sub_821BDA90 (src/mcla_raw_timer.cpp:168, original at :203; guest main thread). Sim end / frame id = VdSwap_entry (xboxkrnl_video.cpp:442, guest render thread), ordinal of the swap. Render submit start = first frame submission in BeginSubmission is_opening_frame (d3d12 command_processor.cpp:5795); render submit end = EndSubmission(true) in IssueSwap (command_processor.cpp:2713/2738), CP thread; CP swap ordinal counter_ (command_processor.cpp:1219). Present start/end around Present (d3d12_presenter.cpp:1176), CP thread in gameplay, frame id carried in GuestOutputProperties at RefreshGuestOutput (presenter.cpp:553-574). CP lag: ids are ordinals, each thread counts its own (timer passes per swap must be 1:1; verify with a counter before trusting, R's design assumes it).
- KI-074 interaction: Reflex/AL2 sleep on the guest main thread throttles the source only when the GPU is the limit (that is exactly when lead 2 and flicker happen); when CP-bound it sleeps ~0. It predicts, so it can cut the GPU bubble our strict fence wait creates (strict/adaptive cost 2-6 fps: 40.6/44.8 vs 46-52), but gives no hard guarantee of lead <= 1 (prediction miss, ring buffer decouples main thread from CP). So complement, not replace: keep frame_lead_adaptive as the guarantee; measure whether adaptive triggers drop with Reflex on. Present(0) path: compatible (Reflex works with interval 0). Guest vblank limiter: leave minimumIntervalUs = 0, otherwise two limiters stack.
- Coverage: NVIDIA Windows: Reflex (driver 456+; GetSleepStatus check). AMD Windows: AL2 (RDNA1+? driver 24.x+; Initialize fails -> off). Intel: neither (XeLL is separate, skip). Wine/Proton: Deck is AMD; amdxc64.dll absent -> AL2 init fails; Reflex under Proton only via dxvk-nvapi + vkd3d-proton VK_NV_low_latency2 on NVIDIA Linux. Policy: under Wine (RunningUnderWine, content_log.cpp:282) never LoadLibrary nvapi64/amdxc64 unless cvar explicitly set; Vulkan backend could later use VK_AMD_anti_lag / VK_NV_low_latency2 natively. Detection: adapter VendorId 0x10DE / 0x1002, LoadLibraryExW(LOAD_LIBRARY_SEARCH_SYSTEM32), init result; one log line, graceful off.
- Design: SDK include/rex/ui/low_latency.h + src/ui/low_latency.cpp (policy, frame ids, stats), src/ui/d3d12/d3d12_low_latency.cpp (NVAPI by QueryInterface with static_assert'd MIT structs; vendored thirdparty/amd_antilag2/ffx_antilag2_dx12.h). Cvars: d3d12_low_latency_mode off|reflex|antilag2|auto (default off), d3d12_low_latency_boost false, d3d12_low_latency_markers_only false (phase 0: markers + GetLatency, no sleep), d3d12_low_latency_presleep_margin_us 1500 (high-res waitable timer pre-sleep to bound NvAPI_D3D_Sleep busy-wait; reuse l79 timer_queue_wait). Host: keys low_latency_reflex, low_latency_antilag2, low_latency_markers. Hook: host strong override at raw timer calls rex::ui::LowLatencyFrameStart(frame_id) before __imp__sub_821BDA90 (mcla_raw_timer.cpp:203), SDK exports it.
- Busy-wait cost: R measured NvAPI_D3D_Sleep 6.4-6.9 ms CPU/frame at a 60 cap. On the 35 W laptop that spin is on the guest main thread, competing with the CP thread for package power. Bound: pre-sleep on the high-res timer until predicted wake - margin (predict from GetLatency gpu/present times or the previous Sleep duration), cap total sleep per frame (e.g. 8 ms) and back off if Sleep > 250 ms; log sleep_ms p50/p99 and spin estimate.
- Counters: MCLA_LOW_LATENCY v=1 mode= frames= sleep_ms_p50/p99 presleep_ms spin_ms_est gpu_ms sim_to_present_ms (GetLatency) frame_end_lead hist (existing last_frame_end_gauge_) adaptive_triggers.
- A/B: PC RTX 5060: arms adaptive (current l91) vs reflex+adaptive vs reflex alone, same route, 1080p and 1440p Unlocked; criteria: no KI-074 flicker, fps >= adaptive, sleep CPU cost, HWiNFO package power/CP clock, subjective input. RX 6800 XT: antilag2 vs off.
- Effort: Reflex markers+sleep DX12 ~500-700 lines + unit tests for frame-id/policy, 2-3 days; AL2 +~150 lines, 0.5-1 day + hardware test; Vulkan variants later. Order: after KI-076 diagnostics and the KI-074 default decision; phase 0 markers-only first (measurement value, no sleep risk).
