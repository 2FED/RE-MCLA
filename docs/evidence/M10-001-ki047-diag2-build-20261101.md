### 1.1 Switch

`d3d12_livery_diag2` (bool, hot reload, SDK default false), independent of
`d3d12_livery_diag` (v1 lines and semantics unchanged; both can be on).
Turning it on logs a `kind=start` line with the settings
(`async_shader_compilation`, both pipeline-wait cvars, readback mode, scale,
budgets) and clears all v2 state; turning it off logs `kind=stop`. With the
cvar off the only per-event cost is one bool test (fence waits, pipeline
waits) or one atomic load (texture loads and invalidations), and the log is
unchanged.

### 1.2 Lines

All lines start `MCLA_LIVERY_DIAG2 v=1 kind=<kind> frame=<CP frame>`. Only
frame and draw numbers, guest addresses, sizes, formats, flags, durations
and pipeline hashes are logged; no guest memory contents, no paths. Each
kind has its own budget of **64 lines per minute** (one-minute window from
the first line), so the world-load burst of one kind cannot starve another;
suppressed lines are counted in the minute line.

1. **`kind=resolve2`**: every read-back resolve of a **sporadic key**
   (address and length of the destination; the previous resolve of the same
   key was 2 or more frames ago, or never), whatever the copy decision.
   Per-frame scene, shadow and bloom tiles therefore do not use the budget.
   Fields: `draw` (draw index in the frame), `mode` (readback mode),
   `scale`, `src` (color/depth), `src_base` (EDRAM base of the source),
   `size` (resolve rectangle in guest pixels), `fmt` (copy destination
   format), `base`, `len`, `since_prev` (frames since the previous resolve of
   this key, -1 = never), `since_copy` (frames since this key's last CPU
   copy, -1 = never copied), `miss` (read-back cache miss: waited and read
   its own slot), `decision` now/deferred/skipped and `reason`, `read`
   this/prev (CPU copy source slot), `prev_age` (submissions since the read
   slot was written; 0 = same open submission, so the GPU copy cannot have
   run), `prev_known_complete` (that submission's fence had passed),
   `prev_len_ok`, `slot_new` (the read-back slot written by this resolve was
   created in this call from a `CreateNotZeroed` heap), `resolves_since_copy`,
   and `cp_wait5_us` = `fence_wait5_us` + `pso_wait5_us` (command-processor
   fence waits and pending-pipeline waits over the last 5 frames including
   the current one, microseconds).
2. **`kind=overlap`**: a read-back resolve whose destination overlaps a
   **different live read-back key** (a buffer of another length or start
   still in the read-back cache, i.e. used within 60 frames): `base`, `len`,
   `size`, `fmt`, `decision`, the most recently used overlapping key
   (`other_base`, `other_len`, `other_last_used_frames_ago`) and
   `overlapping_keys`. One line per key pair per 120 quiet frames; every
   overlapping resolve is counted.
3. **`kind=tex_load`**: a texture-cache load (upload from guest memory, at
   the point the range becomes watched) of a part (`part=base|mips`) whose
   range overlaps a read-back destination of the last 600 frames, or of
   **any 1024x1024 DXT4/5 (BC3) or 2048x2048 8_8_8_8 texture**
   (`atlas_shape=1`). Fields: `base`, `len`, `size`, `fmt` (xenos texture
   format: 20 = DXT4_5, 6 = 8_8_8_8), `tiled`, `packed_mips`, `mip_max`,
   `scaled_resolve`, `first` (first upload of this part since the
   diagnostics started), `reload_without_inval` (loaded again while the
   previous load had seen no invalidation), and the most recent overlapping
   read-back destination: `rb_overlap`, `rb_count`, `rb_base`, `rb_len`,
   `rb_frames_ago`, `rb_copied`, `rb_copy_frames_ago`.
4. **`kind=tex_inval`**: the **first write-watch invalidation** after such a
   load, keyed back to it: `part`, `base`, `len`, `size`, `fmt`,
   `load_frame`, `frames_since_load`, `by_gpu` (1 = invalidated by a GPU
   write such as a resolve, 0 = CPU write). The texture is reloaded on its
   next use, which logs a new `tex_load` and re-arms, so each
   load/invalidation cycle of a tracked texture is visible (within budget).
5. **`kind=pso_wait`**: a pending-pipeline wait of **1 ms or more**
   (measured in microseconds around `AwaitPipeline`): `draw`, `wait_us`,
   `result` completed/timed_out, `mode` always/window, `rt0_base`, `rt0_fmt`,
   `depth_base`, pipeline description and shader hashes, `cp_wait5_us`.
6. **`kind=wait_resolve`**: the **next read-back resolve from the RT0 EDRAM
   base** of such waits (waits into one base are merged until that resolve;
   matched within 600 frames): the resolve's `base`, `len`, `size`, `fmt`,
   `decision`, `read`, and the merged waits `wait_first_frame`,
   `wait_first_draw`, `wait_last_frame`, `waits`, `wait_total_us`,
   `wait_max_us`.
7. **`kind=minute`** (with the existing pacing minute): `resolves`,
   `sporadic`, `sporadic_not_copied`, `sporadic_read_prev`,
   `sporadic_read_prev_unfenced`, `sporadic_new_slot`,
   `overlapping_resolves`, `pipeline_waits`, `long_waits`, `long_wait_us`,
   `wait_resolves`, `tex_loads_tracked`, `tex_loads_rb_overlap`,
   `tex_loads_atlas`, `tex_reloads_without_inval`, `tex_invals`,
   `tex_invals_by_gpu`, `tex_expired` (tracked loads dropped from the
   bounded waiting list), `tex_waiting`, and the suppressed count of each
   line kind.

State is bounded: key history 8192 keys (pruned by age 3600 frames, else
cleared), recent read-back ranges 2048 (600-frame window), waiting loads
1024, first-upload set 8192, pending long waits 16 bases.

### 1.3 Root signature after a pending-pipeline wait (fix in the same commit)

`ConfigurePipeline` returns the pipeline's root signature at configuration
time. For a pipeline still being created asynchronously this is the
placeholder chosen before the pixel shader was translated; the creation
path (`PrepareRuntimeDescriptionForQueuedCreation`) replaces it with the
real one, which can need more texture or sampler bindings. Since the l51
always-on wait, `IssueDraw` waited for the pipeline and then went on with the
placeholder root signature. With bindless resources (the PC configuration)
this was harmless; without bindless it would bind the wrong layout. Now,
after a successful wait, `IssueDraw` takes the pipeline's current root
signature (`PipelineCache::GetRootSignatureByHandle`, chosen by the pure
`SelectRootSignatureForDraw`, unit-tested). Draws whose pipeline was ready,
or that are still skipped, behave as before.

## 5. How to read a broken run

Find the car: the frame of the F10 and the `tex_load` lines with
`atlas_shape=1` or `rb_overlap=1` in the minutes before the police car
appeared (sort by `frame`). The livery path is expected to be a
livery-sized sporadic `resolve2` (32bpp format), followed after a few
frames by a `tex_load` of the atlas whose range overlaps that read-back
destination, or an atlas-shaped load.

- **Candidate 1, stale `some` read-back of a re-used composite key**: the
  livery `resolve2` has `decision=deferred` (nothing copied this time, so
  guest memory still holds the previous composite), or `read=prev` with
  `prev_age=0` or `prev_known_complete=0` (copied a slot whose GPU copy had
  not run), or `slot_new=1` without a wait (recycled VRAM), or `since_prev`
  under 60 with another car's composite on the same key; `overlap` lines
  for the composite range point to the shared-scratch variant (another
  length or format resolved into the same memory). Excluded for that car
  if its resolve is `miss=1 decision=now read=this`.
- **Candidate 2, texture-cache staleness of the atlas**: the atlas
  `tex_load` comes while the guest is still writing (a `tex_inval` with
  `by_gpu=0` and `frames_since_load` of 0-3, followed by a reload; or
  `reload_without_inval=1`), or there is **no** `tex_inval` for the atlas
  although the CPU rebuilt it (missed invalidation; `tex_waiting` stays
  up). A load with `first=1` long after the composite resolve
  (`rb_frames_ago` large) means the texture was built from memory that may
  have been reused.
- **Candidate 3, CP lag against an unsynchronised guest read**: a clean
  livery resolve (`miss=1 decision=now`) but a high `cp_wait5_us` on it,
  and `pso_wait` / `wait_resolve` lines whose RT0 base is the composite's
  `src_base` with tens of milliseconds just before.
- **Candidate 4, EDRAM aliasing**: nothing abnormal on the read-back and
  texture side; the defect would then be in the render target content
  itself, which no v2 line can show (needs a capture).
- The v1 lines (only with `--d3d12_livery_diag=true`) and the l51 wait
  summary still show whether any draw was skipped.

Budgets: the world-load minute will exhaust `resolve2` and `tex_load`; the
livery composite at car spawn during driving normally falls in a later,
quieter minute. The minute line shows how many lines of each kind were
dropped.

## 6. Limits and risks

- Not run: no `MCLA_LIVERY_DIAG2` line has been seen yet; the first owner
  log must show `kind=start`, `MCLA livery diag2: build default
  d3d12_livery_diag2=true`, and plausible `kind=minute` counts.
- Overhead (estimated, not measured): per read-back resolve one hash-map
  lookup and update, one locked hash-map update, and a scan of the live
  read-back keys (at most 256) for overlaps; at about 1,100 resolves per
  second that should stay well under 1% of CP time. Each texture load does
  one locked scan of the recent read-back ranges (at most 2048). Fence and
  pipeline waits read the clock twice. To be checked against l53 in the
  first runs (fps and `cp_busy_ms` of `MCLA_PERF_SPLIT`).
- The livery composite's draw/resolve sequence and the atlas build are still
  inferred (KI-033), not traced; if the atlas is neither 1024x1024 DXT4/5
  nor 2048x2048 8_8_8_8 and is not built in a read-back range, it is not
  tracked (the minute counts still show all overlapping loads).
- `pso_wait` gives the RT0 base and format, not the surface size or pitch.
- Texture invalidation lines are logged from the thread that hit the write
  watch, under the texture cache's global lock (bounded by the budget).
- `cp_wait5_us` counts only command-processor fence waits and
  pending-pipeline waits, not other CP stalls (shader translation,
  uploads); `MCLA_PERF_SPLIT` covers those per minute.
- The root-signature fix changes behaviour only for draws that waited for
  a pending pipeline; with bindless resources (PC) no visible change is
  expected.
- The SDK branch head in `private/l53-sdk-wt` moved from `7892797` to
  `83b093b`; rebuilding `l53-sdk-b` from that worktree would now include
  diag v2 (default off).
- Spark was not used: the work was source edits and builds with exact
  verification, not a bounded extraction or triage task.
