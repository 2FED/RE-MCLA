# M11 l119 owner build (2026-11-20): the shared-memory measurement build (MCLA_SHM, MCLA_FAULT_PROBE), the Canary aed81ca9 unwatched-invalidation fix ON by default, the exact single-range request fast path

**Headline.**
- l119 = main `1e0bec2` (the l118 host plus docs) with a host diff of two keys, built against
  the new SDK `private/l119-sdk-install` (`mcla/m11-l119` `c503e32`, 0.20.0.4-dev.gc503e32; one local commit
  on `8d351cc`; see [M11-l119-sdk-shm-census-20261120.md](M11-l119-sdk-shm-census-20261120.md)).
- **Every run** now logs `MCLA_SHM v=1` (every perf-split window: requests, uploads, the true
  protection-call time, write faults by thread, invalidations, the sampled upload split) and once
  `MCLA_FAULT_PROBE v=1` (the protection fault round trip of the machine; under Proton the Wine
  dispatch, the key unknown of the Deck design). The census part (first touch per submission,
  same-bytes sampling, hot-block R/U) is **off by default**; the `shm-census` arms turn it on.
- **Default behaviour changes** (both in the SDK): the port of Xenia Canary `aed81ca9`
  (`memory_invalidate_unwatched`, ON: a guest protect-to-writable, decommit or release
  invalidates unwatched memory too; a correctness fix; host control `inval_unwatched_off`), and
  the exact single-range request fast path (`shared_memory_single_range_fast`, ON; proven equal
  by unit tests, about 4 ns per request saved). The l118 defaults otherwise unchanged.
- Built and unit-tested only: not signed, not run, no physical PASS.
- **Spark not used**: deterministic source edits, builds and checks; no bounded extraction or
  triage task suited it.

  the census is turned on by the `shm_census` key in the four new arms, and volunteer builds stay
  off (nothing writes the cvar there). The always-on `MCLA_SHM` counters and the probe need no key.
- **m10 defaults:** both cvars join the never-written list (131, was 129); 20 defaults, nothing
  else changed.

## 6. What the owner runs decide (from the SDK document, section 6)

- The vertex-slot numbers stay on `MCLA_VB` (l118); `MCLA_SHM` does not repeat them.
- (a2) compare-before-copy: build if `hot_req_per_up <= 3` and `hot_req_kb / hot_req <= 4` (PC),
  or the Deck projection with `MCLA_FAULT_PROBE dispatch_resume_ns` is at least -3 ms per frame.
- (e1) copy prologue: build if `up_first_sub / up_runs >= 0.5`.
- (c) widening 16 (environment variable, no build): only if `same_share > 0.3`.
- M3 footprint: `unwatched_inval` per minute; non-zero with no visible change is the expected
  outcome; anything odd: an `inval_unwatched_off` A/B.

  release of physical memory now runs the invalidation callbacks (a bitmap clear and the watch

  Run 2 is the overhead check.
