## 1. Fix design

Mechanism addressed: under `some`, a read-back resolve to a key that is
still in the read-back buffer cache (resolved within the last 60 frames) is
not a cache miss, so it does not wait; it is copied to guest memory only
every 4th time, and then from the *previous* slot (the previous resolve of
that key). For the livery composite this leaves the previous car's
composite, or a different mip read through another key of the same scratch
range, in the guest memory from which the CPU builds the car's atlas.

The fix makes such resolves behave exactly like `readback_resolve=full` for
that one resolve: wait for all queue operations (`AwaitAllQueueOperationsCompletion`,
the same fenced wait `full` uses), read this resolve's own slot, and copy it
to guest memory now. Every other resolve keeps the `some` (or `fast`)
behaviour, so per-frame tiles stay cheap. Cache misses are not counted as
forced: they already wait and read their own slot.

### 1.1 Rules as implemented

A read-back resolve in mode `fast` or `some` that is not a cache miss is
forced synchronous when any rule matches:

| Rule | Condition | Scope 0 "composite" (default) | Scope 1 "all" |
|---|---|---|---|
| a, shared range | the destination overlaps another live read-back key (in the 60-frame read-back cache) of a **different length** | only colour resolves from EDRAM base 0 to a k_8_8_8_8 destination | every resolve |
| b, sporadic | the previous resolve of the same key was **8 or more frames** ago (the key is still live, so at most 60) | only colour resolves to a k_8_8_8_8 destination (any EDRAM base) | every resolve |
| c, composite shape | colour resolve from **EDRAM base 0**, **square power of two from 64x64 to 1024x1024** | k_8_8_8_8 destination | 32 bits per pixel |

**Deviation from the requested rules, with the evidence.** The rules as
requested (scope 1) would force about as many fenced waits as `full`: the
l54 cold 1440p log has `overlapping_resolves` of 46,655-50,886 per minute
(about 21 per frame: scene, shadow and bloom scratch re-use such as 256x256
k_8_8_8_8 tiles from EDRAM base 224 inside a 640x640 depth key, and a
128x128/64x64/16x16/8x8 k_32_FLOAT chain from EDRAM base 0 inside another
depth key, every frame); its sampled `resolve2` lines show about 4% of the
2-frame sporadic resolves at `since_prev=49` (k_8 128x128/256x256 tiles
from EDRAM base 224), i.e. roughly 1,500 per minute at the 8-frame
threshold; and the k_32_FLOAT 128x128 and 64x64 levels from EDRAM base 0
would match rule c every frame. Each forced resolve drains the GPU queue in
the middle of the frame, so scope 1 would cost close to what `full` costs
(about 20 fps at 1440p). The default scope 0 therefore restricts the rules
to the family of the livery composite (every composite resolve seen in l54
is a colour resolve from EDRAM base 0 to k_8_8_8_8: level 0 1024x1024, mips
512..8 at 050A0000-051F7000, and the 512x512 composite at 054A0000). In that
family all composite levels are covered: 1024..64 by rule c, the 32x32 and
smaller mips by rule a (they lie inside the live 4 MB level-0 key), and
level 1 at 050A0000 by both. Scope 1 remains available for a direct run
(`--d3d12_readback_sync_scope=1`) if scope 0 turns out not to cover the
defect.

### 1.2 Switches

- SDK: `d3d12_readback_sync_composite` (bool, hot reload, SDK default
  false); `d3d12_readback_sync_scope` (0 or 1, hot reload, default 0).
  Turning the first on or off logs
  `MCLA_READBACK_SYNC v=1 kind=start|stop frame= scope= readback= scale=
  sporadic_min_frames=8 composite_sizes=64-1024 composite_format=6`.
- Host (l55 only, CMake option `MCLA_READBACK_SYNC_COMPOSITE_DEFAULT=ON`):
  at graphics-plugin load sets `d3d12_readback_sync_composite=true` unless
  the user set that SDK cvar, or the init-only host switch
  `mcla_readback_sync_composite` (default true in l55) is false. One log
  line in each case: `MCLA readback sync: fix ON, build default
  d3d12_readback_sync_composite=true`, `MCLA readback sync: fix OFF
  (mcla_readback_sync_composite=false, override file|command line)`,
  `... set by the user (...), left alone` or `... unavailable in this SDK`.
- A/B override file (the launcher cannot pass extra flags): only builds
  with the option ON read `%LocalAppData%\MCLA-R-Launcher-v1\mcla-dev-overrides.txt`
  at graphics-plugin load. It must be a regular file (no directory, no
  reparse point) of at most 256 ASCII bytes holding exactly one line
  `mcla_readback_sync_composite=false` or `=true`, optionally ending in LF
  or CRLF; no spaces, no BOM, no other keys. A valid file is applied unless
  the command line sets `--mcla_readback_sync_composite`; an invalid one is
  ignored. Either way it is logged:
  `MCLA readback sync: override file mcla-dev-overrides.txt found: false
  (applied)` (or `true`, `invalid (ignored; ...)`, `(ignored; the command
  line sets the switch)`). Without the option (every other build) nothing is
  read or written.
- `private/l55-fix-off.cmd` writes that file with
  `mcla_readback_sync_composite=false` (CRLF); `private/l55-fix-on.cmd`
  deletes it. Both refuse to run while `mcla.exe` is running (the file is
  read at game start) and print the result. `l55-fix-off.cmd` writes only
  into an existing launcher folder with `preferences.dat` (the launcher
  refuses a folder without it that holds other files).

### 1.3 Counters

One line per pacing minute while the fix or diag v2 is on, and one at every
F10 (`kind=mark reason=<tag>`, counts of the current minute so far, not
reset):

`MCLA_READBACK_SYNC v=1 kind=minute frame= enabled= scope= mode= resolves=
misses= matched= matched_a= matched_b= matched_c= forced= forced_a=
forced_b= forced_c= forced_wait_failed= wait_ms= max_wait_ms=`

- `resolves`: delayed-mode read-back resolves the rules were evaluated for;
  `misses`: of those, read-back cache misses (already synchronous).
- `matched`, `matched_a/b/c`: non-miss resolves matching a rule (with the fix
  OFF these are the resolves that **would** have been forced: the control
  arm still measures the exposure).
- `forced`, `forced_a/b/c`: resolves actually made synchronous; a resolve
  matching several rules counts once in `forced` and once per rule.
- `wait_ms`, `max_wait_ms`: total and longest synchronous wait of the forced
  resolves (milliseconds, microsecond resolution); `forced_wait_failed`:
  waits that failed (the resolve is then not copied, as in `full`).

## 2. Diag v3 (d3d12_livery_diag2, still on by default)

- **Paced budgets.** Every v2 line kind now has a token bucket (burst 64,
  then 2 lines per second) instead of 64 lines per one-minute window that
  the first frames of each minute used up. The new `composite` kind has its
  own (burst 128, 8 per second). Suppressed counts remain in the minute
  line.
- **Sporadic threshold 8 frames** (was 2, which matched about 16
  every-other-frame tiles per frame), for `resolve2` and the `sporadic*`
  minute counts.
- **`kind=composite` lines.** Every read-back resolve matching sync rule a
  or c (evaluated whenever diag v2 is on, also with the fix OFF) is logged
  with all `resolve2` fields plus `sync_rules` (a/b/c combination),
  `sync_forced`, `sync_wait_us`, `sporadic`, and for a shared range the most
  recently used other key: `other_keys`, `other_base`, `other_len`,
  `other_last_used_frames_ago`, `other_since_prev`, `other_last_copied` (the
  other key's last resolve was copied to guest memory) and
  `other_since_copy`. The `resolve2` lines also carry `sync_rules`,
  `sync_forced` and `sync_wait_us`. A resolve that is both composite and
  sporadic logs one `composite` line.
- **F10 flight recorder.** The last 64 `composite`/`resolve2` lines and the
  last 64 atlas-shaped `tex_load` lines (1024x1024 DXT4/5 or 2048x2048
  8_8_8_8) are kept whether or not their budget let them into the log. F10
  (the existing `MarkPerfSplit` call of the host, now also requesting a
  flight dump whether or not the perf split is on) writes at the next frame
  close: `MCLA_LIVERY_DIAG2 v=1 kind=flight_begin frame= reason=
  resolve_lines= resolve_pushed= atlas_lines= atlas_pushed=`, then one
  `MCLA_LIVERY_DIAG2_FLIGHT v=1 ring=resolve|atlas i=<n>/<count> kind=...`
  line per kept line (oldest first), then `kind=flight_end`. The rings are
  not cleared, so a second F10 shows the same lines plus newer ones.
  `*_pushed` above 64 means older lines were overwritten.
- New minute fields: `composite_resolves`, `composite_not_copied`,
  `composite_read_prev`, `composite_suppressed`. The start line now prints
  `diag=v3`, the budgets, `flight_lines=64` and `readback_sync=`.

## 6. Owner A/B protocol

1. Sign and stage: `private\tools\pwsh\pwsh.exe -NoProfile -File C:\BDU\MCLA-Recomp\private\l55-internal-prepare.ps1`;
   in the launcher set the Build folder to `private\l55-internal\build`
   and press CHECK SETUP. l55 has a new fingerprint, so its first session
   starts on a cold per-build store; the defect is not cache-dependent
   (warm 720p catches on l53), so the A/B uses **warm BENCH copies**: one
   short warm-up session first (any resolution) to fill the store.
2. **Fix ON arm (default; at least 4-5 sessions):** check that
   `private\l55-fix-on.cmd` has been run (or the override file never
   written). Drive laps hunting police cars (several police encounters per
   session), at 1440p and 720p. Press **F10 the moment a livery looks
   wrong**, and also once on a police car that looks correct (a clean
   reference with the flight recorder).
3. **Fix OFF arm (control; 2 sessions):** run `private\l55-fix-off.cmd`,
   then the same kind of sessions; F10 on any broken livery. Run
   `private\l55-fix-on.cmd` afterwards.
4. Send the full session text files (`runtime-*.log`) and the F10 packages
   of every session, broken or clean, and say which arm each session was.

Reading:

- Arm check: the log must show `MCLA readback sync: fix ON, ...` and
  `MCLA_READBACK_SYNC v=1 kind=start` (ON arm), or `override file ...
  found: false (applied)` and `fix OFF` with no `kind=start` (OFF arm).
- Exposure: in both arms `matched`/`matched_c` should rise at car spawns
  (world load, traffic and police spawns). In the ON arm `forced` should
  equal `matched` (`forced_wait_failed=0`); in the OFF arm `forced=0`.

Performance to check against l54 (same route and resolution): fps and

l54, means the rules match routine resolves and must be narrowed.

## 7. Limits and risks

- Not run: no `MCLA_READBACK_SYNC` line has been seen yet.
- The rule narrowing (scope 0) is based on one l54 session; a livery
  composite in another format, from another EDRAM base, or composited by a
  different pass is not covered by rules a/c (rule b still covers
  k_8_8_8_8 keys re-used after 8+ frames). Scope 1 is the fallback.
- The fix does not cover the texture-cache side (candidate 2 of the l54
  analysis): if the atlas is uploaded from guest memory before the CPU has
  rebuilt it, forcing the read-back does not help; the atlas ring of the
  flight recorder is meant to show that case.
- The forced wait is the same full queue drain `full` uses; with many
  composites in one frame (world load) the first wait drains the frame
  backlog and the rest are short. Not measured yet.
- Rule a uses the live read-back cache (keys used in the last 60 frames, at
  most 256), not the longer diag-v2 key history; a composite whose level-0
  key has expired is still covered by rule c down to 64x64, but its 32x32
  and smaller mips then only by rule b (if their own key is live) or not at
  all. The l54 data show mips resolved in the same frame as level 0, so
  this is not expected.
- The override file sits next to the launcher's settings; it is read only
  by builds with the option ON (l55) and only at game start.
- The composite and flight-recorder strings are formatted on the CP thread
  for every sporadic/composite resolve (also when not logged): a few
  thousand per minute at most at the 8-frame threshold.
- Spark was not used: source edits and builds with exact verification and a
  bounded log query done directly; no suitable bounded extraction task.
