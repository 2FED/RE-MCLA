the owner override, user value and availability checks, so a Windows-only entry is never written
under Wine/Proton whatever else holds. `kActionCount` 9 -> 10; the summary lines gain
`windows_only=<n>`, and an entry not written logs `MCLA m10 defaults: <cvar> left at <value>

the Windows-only entries).

## 2. Proof from the SDK source (c403f35, `private/l110-sdk-wt`)

**A. force_hidef is a no-op for modes already HiDef.** `DeriveVideoMode`
(`include/rex/graphics/video_mode_util.h:133-139`): `is_hi_def = force_hidef || width >= 1280 ||
height >= 720` (`:136`); VdQueryVideoFlags bit 1 = `force_hidef || width >= 1024` (`:137`); width and
height are never changed. The cvar's only readers are `VdQueryVideoMode` (`src/kernel/xboxkrnl/
xboxkrnl_video.cpp:241-243`, also the MCLA_VIDEOMODE line `:246-250`) and `VdQueryVideoFlags_entry`
(`:269-279`). For a 1280x720 guest mode both outputs are already set without the flag, so the
forced flag changes only the logged `forced_hidef=1`. The launcher's targets
(`src/mcla_render_target_policy.h:15-20`): 720p, 1440p and 4K are guest 1280x720; only the 1080p
target is guest 960x540 (the one the l107-l110 runs changed). The Deck runs at 1280x720
(docs/M11-priorities.md, Deck section), so A is applied on all platforms. Caveat: the launcher lists
all four targets on every platform; a Deck user who picks 1080p would get the HiDef path there (the
same change that was verified on the PC).

**B. "which wins" for the elision.** The verify is latched when the render target cache is created
(`src/graphics/d3d12/render_target_cache.cpp:479-504`: `elide_verify_enabled_` true only when
`d3d12_transfer_elide_full_overwrite_verify` is on, the path is host render targets and the query heap
and read-back buffer were created). The cut is applied only `if (elide_any_cut &&
!elide_verify_enabled_ && REXCVAR_GET(d3d12_transfer_elide_full_overwrite))` (`:5444-5445`): **the
verify wins**; with the default on, every transfer is still performed and counted, and the line says
`on=1 verify=1` (`FormatElideLine(..., REXCVAR_GET(d3d12_transfer_elide_full_overwrite),
elide_verify_enabled_, ...)`, `:1552-1553`).

**C. "which wins" for the extent bound.** `extent_verify_enabled_` is latched the same way
(`:506-531`). The bound is handed to the common Update as
`SetNextUpdateExtentBound(extent_bound_.guest_rows, !extent_verify_enabled_ &&
REXCVAR_GET(d3d12_draw_extent_from_rect))` (`:1676-1677`); with `apply` false the Update only computes
the bounded lengths (`include/rex/graphics/pipeline/render_target/cache.h:548-556`), and the saving
and the occlusion check are counted from those (`render_target_cache.cpp:5335-5350`). **The verify
wins**: with `d3d12_draw_extent_from_rect` true by default AND `xfer_extent_verify`, the old extent is
used and the saving is still measured (line `on=1 verify=1`, `:1456-1457`). The verify arms therefore
do **not** need the off keys. Only if the verify's query heap could not be created (an
`D3D12RenderTargetCache: failed to create the draw extent verify queries` error) would the bound
apply in a verify arm.

## 8. Risks and limits

- Nothing ran. The defaults were measured only on the RTX 5060 with the 1080p target; Run 1 is the
  first session with them on and no arm.
- The elision and the bound never ran under Wine/Proton or on AMD: the Deck keeps them off
  (Windows-only); AMD Windows gets them on by default without a verify run (Run 4 is the check).
- A Deck user on the 1080p target gets the HiDef path (force_hidef is all platforms); the Deck runs
  so far were at 720p, where it is a no-op.
- A wrong bound would show as stale pixels at the bottom of a surface; Run 1 looks for that by eye,
  pc/verify-gpu measures it (the verify still wins with the defaults on). If the verify's query heap
  failed to be created, a verify arm would run with the bound applied (logged as an error).
- The m10 defaults also act in volunteer builds (`MCLA_M10_SPEEDUP_DEFAULTS`); an SDK without these
  cvars (e.g. the gate SDK v0.20.0.8) logs each entry as `unavailable`.
- Arm names that used to differ from the default (pc/hidef, pc/elide, the `-sd` arms) are now the
  defaults; the checklist and helpers say so and point at gpu-old / hidef-only / extent-off.
