### Deviations from the proposal diff

1. Update-path re-arm is limited to the updated slot (the proposal re-armed all
   slots on every update), as the task brief specified.
2. Per-slot re-arm budget (10 per minute, `rearm-limit` line) added; the
   proposal had no bound.
3. Policy moved into a header with injectable status/run callables so it is
   unit tested; the driver passes SDL lambdas.
4. Retype detection also requires an existing host effect (`effect_id >= 0`);
   the proposal compared against stale slot state.
5. The batch audit line also records raw r5/r7 and the first word of entries
   0 and 1.
6. The watchdog also requires `is_wheel` and input-active (not only `haptic`).

1. Start l47 with the wheel active; drive normally (centering and engine

5. Note whether `XINPUTD_FF_AUDIT v=1 export=EffectOperation action=batch`

6. Any `rearm-limit` or `rearm failed` line: report it with the log.
7. If force is still lost with **no** rearm line: say whether pad -> wheel or

   "playing", or a title-side stop).

## 5. Limits and risks

- Unverified physically. Unit tests exercise the policy with a fake haptic
  layer, not the SDL/DirectInput calls or a T300.
- If the T300 driver reports a device-stopped infinite effect as playing, the
  watchdog cannot see it (status is the only signal); a bounded unconditional
  re-start on triggers would be the next step and needs physical evidence.
- The batch path trusts r5 as the entry count with a two-word stride
  (documented in the hook comment, not yet seen in a real batched call). If a
  title passes count > 1 with another layout, extra entries would be decoded
  from the following words; invalid indices are rejected
  (`X_ERROR_BAD_ARGUMENTS` / slot without effect), but a valid-looking word
  could start/stop a wrong slot. The audit line exists to confirm this.
- Update-path re-arm queries `SDL_GetHapticEffectStatus` once per same-type
  update of a running infinite effect (possibly per frame). The start path
  already does the same per infinite start; the cost on the T300 driver is not
  measured.
- A re-armed effect restarts from its beginning (envelope attack); for
  spring/damper/periodic this is expected to be imperceptible.
- Dev SDK (unpinned, `0.20.0.1-dev.g28ac239`); the host was configured with an
  empty `REXSDK_VERSION`. Not suitable for volunteers until the SDK change is
  published and pinned.

## 6. Unconditional resync (SDK commits 9403b29 + 610cc21 + daa1ae5) and the refreshed l47

Status 2026-10-30: implemented, built and unit-tested by an Opus subagent;
**not physically verified**. Nothing pinned, published or pushed. The l46

### 6.1 Why the resync is unconditional

The tester packages (T300RS, PC mode, firmware 34.00, driver 2.11.57.0) show the
centering spring and the engine vibration vanish at the race start and at
slow-motion transitions with **no** stop line, error, device-control line,
routing change or reconnect. The 12:38:42 focus resume found the spring still
reported as **playing**, and the l46 start path skips an infinite start silently
on that status. The likeliest reading is that the T300 driver drops the infinite
effects and keeps reporting them as playing. A status-based re-arm (28ac239,
sections 1-5) cannot see that. The owner confirmed that Alt-Tab restores
centering every time. The focus path stops all effects and runs the preserved
infinite effects again **without re-sending parameters**, so the parameters
held on the device are intact. The resync repeats that sequence on bounded
triggers.

### 6.2 SDK change

- Repository `private/l39-sdk-src`, branch `mcla/ki-022-ffb-rearm`, new local
  commit **`9403b297525fb32cc884c557cbb9d945a9ed9507`** on top of `28ac239`
  (author Bolodymyr). It was made in a linked worktree
  `private/l47-sdk-wt` (detached) and fast-forwarded into the branch.
  `mcla/ki-040-xinput-rescan` is unchanged. Not pushed. 4 files, +971.
- Coordinator refinement, second local commit
  **`610cc21`** (full SHA below in 6.3) on top of `9403b29`, same author:
  the pass now repeats the focus-resume sequence exactly. It issues **one
  global `SDL_StopHapticEffects`** on the wheel, then `SDL_RunHapticEffect`
  for every believed-running infinite slot in slot order with the stored
  iterations. Finite effects in flight are cut by the global stop, as on
  Alt-Tab. The global stop is used only when every candidate slot has resync
  budget, so a slot over its limit is never stopped without being run again.
  A periodic pass with such a slot is skipped. A host/burst pass falls back
  to per-slot stop + run for the slots with budget and logs one limit line
  for the refused slot. A failed global stop logs
  `SDL wheel FFB <reason> resync stop-all failed: <err>; per-slot stop and run`
  and falls back to per-slot stop + run. 3 files, +161/-24. The per-slot
  description in the next bullets is now the fallback path only.
- Coordinator refinement, third local commit
  **`daa1ae5f751a55461a5f57e7a42677b6210240ed`** on top of `610cc21`, same
  author. The global stop must not cut an impact in flight, so:
  - The periodic pass now also requires a quiet window: no finite-effect start
    within the last 1000 ms (`kWheelResyncQuietMs`). While impacts keep
    coming, the pass is deferred. The 10 s timer is kept and no budget is
    spent, so it runs at the first quiet poll.
  - A host request waits for the same quiet window up to its 2 s expiry, then
    runs anyway (`WheelResyncRequestSlot::Poll`). A request that no poll saw
    before its expiry (no focused wheel) is still dropped as stale.
  - A deferred host request joins a burst-end pass, because that pass stops
    the device anyway; such a pass is logged with the host reason.
  - The burst trigger keeps its 300 ms settle.
  - 3 files, +135/-5.
- `include/rex/input/sdl/wheel_force_feedback_resync.h` (new, SDL-free policy
  plus the public API, feature macro `REX_INPUT_SDL_WHEEL_EFFECT_RESYNC`):
  - `void rex::input::sdl::RequestWheelEffectResync(const char* reason)`:
    thread-safe (mutex), coalesced (one pending pass, first reason kept),
    executed on the `GetState` poll path of the active focused wheel. It
    expires if not executed within 2 s. The reason is normalised to
    `[A-Za-z0-9._-]` (max 32 characters) and a leading `host:` is not repeated.
    It is a no-op without a wheel or with `wheel_force_feedback` off.
  - Resync of one slot (9403b29; since 610cc21 only the fallback) =
    `SDL_StopHapticEffect` then `SDL_RunHapticEffect` with the stored
    iterations, in slot order. It applies only to slots the host
    believes are running, with a created effect and INFINITE duration. The
    device status is never queried, so the start path's status-playing skip
    does not apply. Parameters are not re-sent. Finite effects and effects the
    host believes are stopped are never touched. The constant slot with
    policy gain 0 is included (it is believed running).
  - Triggers: (a) host request, `reason=host:<tag>`; (b) burst end: at least
    4 finite starts within 2 s arm it, and it fires once 300 ms after the last
    finite start (never inside the burst; the race-start burst was 28 starts
    on one slot within 0.76 s), `reason=burst`; (c) periodic: every 10 s
    since the last resync pass of any trigger, only while input is active
    (focused), on the active wheel, with at least one candidate slot,
    `reason=periodic`. A host request and a burst end at the same poll run
    as one host pass.
  - Bounds: at most 6 resyncs per slot per 60 s window (shared by all
    triggers) and one
    `SDL_WHEEL_FFB_EFFECT v=2 action=resync-limit slot=N type=T reason=R limit=6 window_ms=60000`
    line per window. A periodic pass keeps 1 attempt in reserve for the
    event-driven triggers (so periodic alone gives at most 5 per window; with
    nothing else happening, one periodic pass per minute is skipped silently).
    The resync budget is separate from the 28ac239 re-arm budget.
  - Log: `SDL_WHEEL_FFB_EFFECT v=2 action=resync slot=N type=T reason=host:<tag>|burst|periodic`.
    A failed run logs `SDL wheel FFB <reason> resync failed for slot N type T: <err>`,
    keeps the running belief and consumes budget.
  - Update visibility (coordinator refinement 6): a later update (after the
    first) whose neutral state (gain 0, or zero strength for the type) or
    finite state differs from the slot's previous update logs
    `SDL_WHEEL_FFB_EFFECT v=2 action=update-change slot=N type=T neutral=0|1 finite=0|1 duration=D gain_percent=G`
    plus the `SDL_WHEEL_FFB_PARAMS ... action=update-change` parameter line.
    The limit is 6 per slot per minute, with one `action=update-change-limit` line.
    Create, retype and the first update reset the state without a new line.
- `sdl_input_driver.h/.cpp`: `WheelEffectState` gains `resync_budget` and
  `update_change`; `ControllerState` gains `force_feedback_burst` and
  `force_feedback_resync_ms`; new `ResyncWheelEffectsLocked` and
  `ServiceWheelEffectResyncLocked` (called from `GetState` after the 28ac239
  watchdog). Every successful finite start feeds the burst tracker. The 28ac239
  status re-arm, batch handling, retype and start-suppressed lines are kept
  unchanged.
- The optional per-resync dump of the last host parameters (refinement 2) was
  not added. The `create`/`first-update`/`update-change` lines already carry
  the parameters, and the Alt-Tab evidence says the device copy is intact.
- All new lines contain `SDL_WHEEL_FFB`, so the host's L2 FFB array captures

### 6.7 Limits and risks

- Unverified physically. The unit tests use a fake haptic layer and a fake
  clock, not SDL/DirectInput or a T300.
- Since 610cc21 the normal pass uses the same global stop as the focus
  path. Only the fallbacks (global stop failed, or a slot over budget on a
  host/burst pass) use per-slot stop + run, which is not proven on the T300.
  Since daa1ae5 the periodic and host passes wait for 1 s without a finite
  start. A burst-end pass (300 ms after the burst) and a host request that
  reaches its 2 s expiry can still cut a finite effect that is playing, as
  on Alt-Tab.
- The periodic resync restarts the spring every 10 s. A restart from the
  beginning (envelope attack) is expected to be imperceptible for
  spring/damper/constant, but this has not been felt on a wheel yet.
- Host triggers depend on the M9-007 hook seeing the pause edges (stock and
  unlocked mode alike). If `mcla_ui_cap_guest_pause=false`, only the burst
  and periodic triggers remain.
- The SDK version string still says `g28ac239`. The dev SDK is unpinned and
  unpublished, so the build is not suitable for volunteers until the SDK change
  is published and pinned.
