## 1. What changed vs l83, and why

**H1 refuted by the l83 PC run.** The owner's l83 PC F10 packages had the `ambient_dt` block with `windows=0`, `worker_steps=0` and `outside=[2606,2100,0]` / `[17887,26164,0]`: the probe was live, but no kick/join window ever opened. Static reason (now pinned in `tests/mcla_ambient_dt_probe_test.cpp`):

- the kick `bl 0x826d9578` at 0x822C26B8 in `sub_822C1FA8` is skipped unless the ambient manager pointer 0x8286D8E4 (`lwz r11,-10012(r22)`) is non-null and its byte mgr+0x64259 (`ori r21,r11,16985`, `lbzx r10,r11,r21`) is non-zero; there is no other path to the kick;
- the manager constructor `sub_826D8E70` stores that byte as (word +4 of 0x8288E8F4 != 0) (`lwz r9,4(r4)`, `cntlzw r4,r9`, `rlwinm r4,r4,27,31,31`, `xori r8,r4,1`, `stbx r8,r31,r15` with r15 = 0x64259); `sub_822D3D38` stores the constructed manager at 0x8286D8E4;
- 0x8288E8F4 is a command-line parameter object registered by the static initialiser `sub_827AE6B0` through `sub_821C06C8`, which stores 0 at +4. Only the command-line parser can set it (not checked statically; the runtime `threaded=` field of the v2 lines reports the byte).

So on a retail start the "[MC] Ambient Traffic" worker is never kicked, and the ambient step `sub_826D75D8` runs **inline on the main thread** from `sub_822D3C20` (return 0x822D3D20) with r3 = the same manager. H1 as written (the worker reads a split delta) does not apply, and `ambient_dt_snapshot` (served only inside a kick/join window) is inert in retail. The key is kept so arm files stay valid; it is in no l84 arm. The l83 implementation evidence has a matching addendum (s.9).

**A1, probe v2 (`ambient_dt_probe`, same key and cvar; `src/mcla_ambient_dt_probe.{h,cpp}`).** Still read-only and default off; with the switches off every hook is one static bool test. New:

- the inline call of `sub_826D75D8` (lr 0x822D3D20) is counted (`inline_steps`); at its entry the main timer +8 (seen delta), +80 (saved full delta), +73 (split flag), +76 (split count) and the manager byte mgr+0x64259 (`threaded`) are sampled; site A/B/C reads made during the step are attributed to it (`inline_reads`, a subset of the v1 `outside` counters, which keep their meaning "not by the worker");
- every site A/B/C read on any thread records whether +73 is set at that moment (`split_any`) and, when set, whether the seen delta differs from +80 (`split_short`, `max_split_ratio` = largest +80 / seen);
- the raw timer calls `MclaAmbientDtOnTimerUpdate` after each main-timer tick (`sub_821BDA90` on 0x827D7500) has run, with the +8 the game applied and the step the raw timer supplied; the probe counts `timer_updates` and a histogram of inline steps per timer update (`steps_per_update` 0 / 1 / 2+), and per inline step `timer_mismatch` (seen delta differs from the latest update's +8), `split_at_step` (entered with +73 set), `step_jumps` (more than 20 % away from the previous inline step's delta), `max_step_ratio` and the step delta min/max;
- one `MCLA_AMBDT v=2` line every 300 inline steps (or 300 kick/join windows, if a worker ever runs), plus one `kind=start path=inline` line at the first inline step and one `kind=start path=worker` line at the first kick (if it ever happens); the F10 `ambient_dt` block is `"version": 2` with the new fields; the v1 window counters are kept in both.

Example line (from the unit test: 300 inline steps, one per timer update, one frame where the step saw dt / 2 during a racer split; one line in the log, wrapped here):

```
MCLA_AMBDT v=2 probe=1 snapshot=0 threaded=0 inline_steps=300 timer_updates=300
  steps_per_update=0/300/0 split_at_step=1 step_jumps=2 timer_mismatch=1
  step_dt=0.020000/0.040000 max_step_ratio=2.0000 inline_reads=300/1200/0 split_any=0/1/0
  split_short=0/1/0 max_split_ratio=2.0000 last_step=[0.040000:0.040000:0:0:0.040000:0.040000]
  window=0 windows=0 overlaps=0 racer_splits=0 racer_outside=0 worker_steps=0 split_reads=0
  reads=0/0/0 split=0/0/0 outside=300/1200/0 served=0/0 max_abs_dt_delta=0.000000
  min_ratio=1.0000 kick_dt=0.000000 join_changed=0 kick_split=0 last=[]
```

`last_step` = `[dt:full:split:n:timer_dt:applied]` of the most recent inline step (`applied` = the raw-timer step, -1 without the raw timer). The timer configuration probe build (no `mcla_raw_timer.cpp`) has no timer-update hook, so `timer_updates` stays 0 there.

**A2.** `ambient_dt_snapshot` is unchanged in code, marked inert in retail in its cvar description, the probe source comments, `mcla_dev_overrides.h` and the l83 evidence addendum.

**A3, new dev key `raw_timer_stats`** -> host init-only bool `mcla_raw_timer_stats=true` at startup (=false writes nothing, no conflict pair; host-owned, added to `kNeverWrittenCvars`, 67 -> 68). 79 -> **80 keys**. On this arm the existing `MCLA timer stats: ...; hitches N hold 0|1` line appears every 300 raw-timer updates, and it gains appended fields only: `; applied min/avg/max a/b/c ms measured min/avg/max d/e/f ms; far N debt X s` (`far` = updates whose applied step is more than 20 % away from the measured one; `debt` = the smoother's current debt). The pure part is `mcla::raw_timer::StepRange` / `FarFromRaw` in `src/mcla_step_smoother.h` (unit-tested).

**A4, KI-075 launcher prefill (`src/mcla_launcher_ui_win.{h,cpp}`).** New pure `DefaultDestinationParent(action, selected_managed_root, collection_parent)`: a new (no retained draft) Copy selected profile / Restore snapshot / Import form starts with "Destination parent for the NEW profile" = the parent folder of the selected managed profile's root; Create keeps the controller's collection-parent hint and falls back to the same parent; Register (an existing root), Rename and every other action get nothing; no selected managed profile (or a legacy read-only one) gives nothing. A retained draft still wins. Path validation on submit is unchanged.
