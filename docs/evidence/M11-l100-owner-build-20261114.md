# l100 owner-internal build: Deck command-processor levers, guest spin census (2026-11-14)

Owner-internal candidate l100, implemented, built and staged by an Opus subagent for the primary
agent overnight (owner away; builds allowed). **It has been built and unit-tested only. It is not
signed and has not run in the game, so there is no physical PASS.** l100 builds against a NEW
SDK, `private/l100-sdk-install` (SDK `1e81149` on `mcla/m11-l100`, see
[l100 SDK](M11-l100-sdk-deck-levers-20261114.md)); all seven pins are new. l100 is a superset of
l99: every l99 arm is kept with an unchanged body. Basis: the Deck census of
[l96 Deck analysis](M11-l96-deck-analysis-20261113.md) (type-0 register writes 3.22 ms per frame,
66 % of float constant dwords unchanged, 11.9 k constant uploads per frame) and the macXenos spin
note ([survey](M11-macxenos-survey-20261113.md) item 8).

Guardrails:
- Nothing was launched (no `mcla.exe`, no launcher). No save, profile, ticket, key or registry
  entry was written. The arm helpers were dry-run against a scratch `LocalAppData`; the real
  per-user override file was not touched (same SHA-256 before and after the dry run).
- No git write in the main repository; the SDK commit is local on `mcla/m11-l100` (not pushed).
- `private/tools/wait-for-idle-pc.ps1` ran before every build and test command (every step
  started on IDLE).
- No l99 file was changed.
- **Spark was not used:** deterministic implementation, build and staging work, checked by
  tests.

and one `kind=config` line; host `MCLA_SPIN v=1` per perf-split window (formats: the SDK

qualify and whether pipeline / render targets / shader translations / primitive setup ever differ
